# 가구 강도 이후 소유량과 방 배치

2026-09-28 · `codex/village-life-and-economy`

가구 강도는 서버가 가구 보유 수량을 양쪽 계정 사이에서 옮기는 동작이다. 방 프로필에 예전에 배치해 둔 사본이 남아 있어도, 현재 보유 수량을 넘어 다시 표시하거나 저장할 수 없어야 한다. 이 문서는 이 보조 규칙만 기록한다. 강도 확률·일일 횟수·방범 물품·대상 조건은 금융 구현과 별도 기능 설계를 따른다.

## 저장 계약

| 값 | 의미 |
| --- | --- |
| `life.ext[uid].furn[ref]` | 서버의 현재 보유 수량. 가구 소유량의 기준이다. |
| `life.ext[uid].furnStrict[ref] = true` | 이 가구는 예전 방 배치의 예외 허용을 받지 않고 현재 보유 수량을 따른다. 영구 표시이며 수량이 아니다. |
| `lifeView.me.furnitureStrict` | 본인 방의 즉시 표시·편집에 쓰는 동일한 표시의 읽기 전용 사본이다. |
| `life.rooms[uid].rev` | 열려 있는 친구 방이 수정된 배치를 다시 읽게 하는 기존 갱신 신호다. |

성공한 가구 강도는 피해자의 수량을 1 줄이고 수령인의 수량을 1 늘린다. 양쪽에 같은 `furnStrict` 표시를 남기고 방 revision을 올린다. 이 값들은 가구 수량 변경과 같은 world commit에 속한다. 거절·방범 물품 차단·실패한 강도에는 이 표시를 새로 남기지 않는다.

읽기 파서는 실제 가구 목록에 있는 ref와 정확한 `true` 값만 보존한다. 클라이언트가 보낸 방 프로필로 표시를 지우거나 보유 수량을 늘릴 수 없다.

## 방에 적용하는 방법

`app/lounge-furniture-protection.ts`의 순수 함수가 저장된 배치 순서를 유지하면서, 표시된 ref를 현재 보유 수량만큼만 남긴다. 같은 ref가 여러 번 나올 때 앞에서부터 남긴다. 원본 프로필 객체를 변경하지 않으며, 표시가 없는 다른 ref와 방의 스타일은 보존한다.

다시 가구를 구매하면 현재 보유 수량이 늘어나므로 그 수량까지 배치할 수 있다. 표시 자체를 지울 필요는 없다. 이 방식은 예전 배치를 무제한 소유권으로 바꾸지 않는다.

기존 방 저장 검증은 예전에 저장된 일부 소품을 예외 허용한다. 표시된 가구는 새 입력과 이전 방 모두 먼저 제한한 뒤 검증하므로 그 예외 경로로 도난 사본을 다시 저장할 수 없다. 과거 프로필·백업을 강도 직후 일괄 수정하거나 삭제하지 않는다. 이후 사용자가 방을 저장할 때는 유효한 배치만 저장한다.

## 적용 경로

- 로그인·계정 프로필 응답: 현재 world의 소유량으로 방을 제한한다.
- 방 저장: 새 입력과 이전 프로필에 같은 정책을 적용한다. 성공 응답과 저장 충돌 응답도 최신 world로 다시 제한한다.
- 친구 방 방문: 이미 읽는 world의 소유량으로 방문 화면을 만든다. 방 revision 변경은 열려 있는 방문 화면의 재조회에 연결된다.
- 내 방: `BedroomEditor` wrapper가 현재 life view를 사용해 표시와 편집 결과를 제한한다.
- 서버 방 점수: world CAS 시도마다 유효한 배치를 다시 계산해 숨겨진 사본이 아늑함 점수에 더해지지 않게 한다.
- 클라우드 저장 확인: 클라이언트는 서버가 돌려준 유효한 저장본을 반영한다. 응답을 기다리는 동안 발생한 더 새로운 편집은 덮어쓰지 않는다.

## 저장 경쟁과 한계

world와 profile은 별도 CAS를 사용한다. 배치 수량을 한 번 조회하는 것만으로는 조회 직후의 방 저장과 강도가 서로 엇갈리는 문제를 막을 수 없다.

이 구현은 새 SQL 트랜잭션이나 스키마 변경 대신, 현재 world의 소유량을 모든 표시·검증 경로의 기준으로 삼는다. 예를 들어 프로필 저장 검증 때 2개를 보유했더라도 저장 도중 강도로 1개가 되면, 최신 world를 읽은 저장 응답에서는 1개만 돌려준다. 저장 충돌이 반환한 과거 프로필에도 같은 제한을 적용한다. 따라서 원본 프로필에 오래된 사본이 남는 것 자체를 실제 소유권으로 취급하지 않는다.

기존 화면은 다음 world 갱신·방 재조회 전까지 잠깐 이전 배치를 보여 줄 수 있다. 소유 수량 이동과 금전 처리는 서버 world가 결정하며, 화면의 남아 있는 사본으로 추가 가구를 소유하거나 서버 방 점수를 얻을 수 없다. 배치에서 숨겨진 가구 위의 다른 소품 위치를 자동으로 재배치하지는 않는다.

7인의 기본 방은 잠금 가구 ref를 포함하지 않는 기존 회귀 검사를 통과한다. 따라서 `null`·과거 버전 방을 기본 방으로 읽는 경로가 이 제한 대상의 사본을 복원하지 않는다.

## 검증

`tests/lounge-furniture-protection.test.mjs`는 다음을 검증한다.

- 2개 보유·2개 배치에서 강도 이후 피해자 1개와 수령인 1개로 이전되고, 피해자 화면에는 1개만 남는다.
- 원본 프로필과 관련 없는 예전 가구 배치는 보존된다.
- 표시가 저장·읽기·본인 life view·프로필·친구 방문을 거쳐 유지된다.
- 오래된 방 재전송과 방 필드 없는 구형 저장도 소유량 제한을 우회하지 못한다.
- 재구매한 수량만큼 배치가 다시 가능하며 그보다 많은 사본은 허용하지 않는다.
- 실제 API 핸들러를 로컬에서 실행하고 RPC만 대체해, 저장 도중 강도와 저장 충돌 응답의 제한을 검증한다. 외부 서비스 요청은 수행하지 않는다.

신규 6개 검사와 기존 방·계정 보안 20개 검사가 통과했다. 변경 파일의 type-aware lint와 diff 검사를 통과했다. 전체 통합 검사는 상위 작업에서 수행한다.
