## 체스 판정의 범위

시간패는 상대가 강제로 메이트를 만들 수 있는지가 아니라 가능한 합법 수순 중 메이트가 존재하는지에 영향을 받는다. 상대 폰이 자기 킹의 퇴로를 막는 나이트 메이트, 반대색 비숍이 퇴로를 막는 비숍 메이트를 실제 합법 수순 `Nf7#`, `Bf3#`로 검사한다. 나이트 대 킹/퀸만 있는 경우, 같은 색 비숍만으로 메이트를 못 만드는 경우 등 확실한 기물 부족을 유지한다.

모든 봉쇄·강제 수순의 dead position을 탐색하는 해결기는 추가하지 않았다. 기존 자동 3회 반복·50수 규칙도 이 게임의 기존 방식으로 유지한다. 따라서 모든 FIDE 대회 규정 전체를 구현한 엔진이라고 설명하지 않는다. 실제 시작판에서 72수를 모두 합법 입력한 뒤 시간패 정산·중복 수 거절·장부 보존도 확인한다.

## 검증

기존 8종 엔진의 합법 수·비공개 정보·정산·시간 초과·재접속 회귀를 전체 실행한다. 새 입력 잠금, 베팅 미리보기, 체스 실제 메이트/서버 정산, 고스톱 실제 표시, 낚시 복수 입력과 서버 재생 회귀를 포함한다. 브라우저는 두 화면(1280×720, 1920×1080)에서 실제 입장·관전·새 선택/확정·거절 후 보존·전송 피드백·키보드와 조작영역을 확인한다. 긴 화면 캡처 중 실제 통신 요청을 잡아 두지 않는다.

합성 fixture는 새 초대의 실제 형성 상태와 화면의 판 ID·버전 반영을 기다린 뒤 조작한다. 고스톱의 별도 `ply` 계약과 지연 표시도 확인한다. 이전 관전 판은 실제 합법 입력으로 끝내 정산한 뒤 새 판에 입장한다. 게임 시간 제한 연장은 해당 합성 판에만 적용하며 요청 큐·전송 제한·재시도 규칙을 바꾸지 않는다.

로컬 `npm run check`는 타입·전체 테스트 1,381/1,381·lint를 통과했다. CSS 토큰 검사는 모든 항목 0, 글꼴 생성과 일반/프로덕션 경로의 Pages 빌드도 통과했다. 낚시 손맛은 실제 화면에서 두 키를 함께 누른 뒤 하나만 떼어도 누름 상태가 유지되고, 마지막 키를 뗄 때 해제됨을 확인했다. 기존 접근성 등 lint 경고는 남아 있다.

두 화면의 최종 테이블 검증은 16맥락·48기능 단계·54정상 캡처·16관전 정보 검사로 구성했고 모두 통과했다. 저대비·작은 글씨·잘림·가림·겹침·가로 넘침과 예상 밖 페이지·콘솔·API·리소스 오류는 0이다. 라이어 제시어 힌트의 의도된 거절은 화면별 한 번씩 기록했다. 변경한 다섯 게임은 시각 보완 후 두 화면을 재검증했고, 합성 보고서는 각 실행의 원본 빌드·보고서 경로를 보존한다. 낚시는 표시 함수와 실제 수첩 SSR의 141종을 서버 희귀도 네 분류와 대조했다.

새 CI `minigames (cards/boards, s/fhd)` 네 작업은 실제 입장·관전·결정·정산과 화면 품질을 검사하고, 각 작업의 `summary.json`·`metrics.csv`·스크린샷을 항상 아티팩트로 남긴다. 기존 이동·유찬 집·친구 모임·공동 주문·생활·전체 UI 작업도 유지한다. 공개 배포는 예상 커밋의 현재 청크와 HTML/CSS 바이트를 비교하고 API OPTIONS만 호출해 확인한다.
