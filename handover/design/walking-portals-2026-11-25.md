# 주민 보행·클릭 이동·포탈 패치

2026-11-25. 사용자 피드백: NPC가 뭉쳐 이동함, 이동이 매끄럽지 않음, 넓어진 맵에 포탈이 필요함.

## 주민 보행

공유 일정에서 주민 모두 같은 속도로 공통 경로를 걸었고, 귀가 시작 시각도 같았다. 개인별 정지 위치가 달라도 경로가 합쳐지면 오랫동안 겹쳤다. `lounge-npc-schedule.ts`에서 주민별 결정적 보행 속도·귀가 출발 간격·출입문 통과 간격·보행선을 계산한다. 날짜나 프레임마다 임의로 좌표를 흔들지 않는다. 보행선은 실제 통행 검사를 통과한 경로에만 적용하며 일정의 목적지와 기존 사회적 산책·동행은 유지한다. 서버가 판단하는 대화 위치도 같은 일정을 사용한다.

같은 세 게임일을 1초씩 주입한 비교에서 0.85m 이내 동시 보행은 696→303 pair-seconds, 세 명 이상 뭉친 시간은 50→5초, 15cm 이내 연속 중첩 최장은 47→6초였다. 루미·로제의 장시간 완전 중첩은 재현되지 않았다. 이는 일정 모델의 재현 결과이며 실제 사용자 기기에서 측정한 FPS나 모든 순간의 겹침 제거를 뜻하지 않는다.

같은 가상 친구 여덟 명과 이전 scheduler만 주입한 별도 Node 프로세스로 비용을 비교했다(모듈 import 시간 제외). `lifeView` 첫 호출은 11.031→11.050ms, 따뜻한 30회 중앙값은 1.216→1.279ms였다. 주민 29명 위치의 첫 계산은 289.274→305.441ms, 따뜻한 30회 중앙값은 0.0127→0.0126ms였다. `lifeView`는 동선 전체를 계산하지 않는다. 경로 캐시는 날짜에 따라 무한 증가하지 않도록 제한한다.

## 클릭 이동

일부 장면은 한 프레임에 경유지 하나만 처리하여 꺾이는 지점에서 남은 이동 거리를 버렸다. `lounge-walk-route.ts`로 같은 프레임의 잔여 거리를 다음 경유지에 사용한다. 실제 맵·가구 충돌의 작은 이동 단계는 유지한다. 공용 프레임 시간은 최대 0.5초로 제한하여 저속 화면 갱신 시 지나친 감속을 줄이고, 오래 멈춘 탭의 시간을 한꺼번에 이동하지 않는다.

네트워크 이동은 최신 샘플을 합쳐 보내는 기존 주기와 요청 순서를 유지한다. 전송 대기 중 낡아진 좌표와 구역 전환 뒤 남은 이동 요청을 다루며, 인증·요청 번호·재시도 영수증·원자적 커밋은 유지한다. 서버 이전이나 요청 빈도 증가는 이번 패치에 포함하지 않는다.

## 마을 포탈

`lounge-portals.ts`가 아홉 구역의 고정 위치·표시 이름·사용 거리·해금 판단을 공유한다. 마을 광장, 우리 농장, 시장 거리, 항구 구역, 언덕 주택가, 목장·과수원, 산기슭 마을, 뒷산, 숲 깊은 곳에 둔다. 지도에서 포탈까지 걸어간 뒤 E로 목적지를 고른다. 열린 구역 사이의 이동은 무료다. 잠긴 목적지에는 기존 해금 조건을 안내한다.

`{kind:'portal',to}` 요청은 클라우드 엔진이 출발지의 실제 좌표·포탈 거리·낚시·테이블 자리·목적지 해금을 검사하고 정규 `area` 이동으로 변환한다. 도착 좌표는 서버의 고정 데이터만 사용한다. 사용자가 넣은 임의 좌표·집 주인·광산 층·먼바다 목적지는 받아들이지 않는다. 구역 방문 기록은 기존 이동과 같이 남는다. 새로운 DB 테이블이나 저장 스키마는 필요 없다.

도착 화면은 성공한 서버 응답을 따른다. 지도에서 포탈까지 걷는 행동 자체는 구역을 바꾸지 않는다. 이동 전 모임 길 안내를 취소하여 이전 구역의 안내가 뒤늦게 덮어쓰지 않게 한다.

지도에서는 바닥돌 위치를 표시하고 지도 아래의 44px 도보 버튼으로 이동한다. 친구 위치와 포탈 위치가 겹쳐도 양쪽 조작이 가려지지 않는다. 요청 중에는 목적지 중복 선택과 Esc 닫기를 막고, 서버 승인 뒤 장면 전환까지 기다린다. 간편 화면에는 3D 지도와 E 사용 방법을 안내한다.

## 검증 범위

순수 일정·경로 검사, 실제 클라우드 전이의 잠긴 목적지·원거리·잘못된 목적지·낚시·착석 거절, 고정 도착점, 재접속·영수증 재시도, 재화 불변과 기존 구역 방문 기록을 확인한다. 화면 검사는 로컬 빌드와 가상 계정으로 진행하며 운영 계정이나 마을 저장을 수정하지 않는다.

로컬 `npm run check`는 타입 검사·전체 테스트 1,360/1,360·lint를 통과했다(기존 접근성 등 lint 경고는 남아 있다). `npm run lint:css -- --ci`는 회귀 없음, 글꼴 생성과 일반/프로덕션 경로의 Pages 빌드도 통과했다.

`verify-walking-portals-ui.mjs`는 1280×720 승준/1920×1080 유찬의 가상 세계에서 12단계·14캡처를 통과했다. 실제 도보와 E, 요청 중 Esc·방향키·중복 선택, 해금/탐험권, 의도한 서버 409 거절 후 제자리·창 유지, 지연된 모임 안내 취소, 시장 왕복 뒤 기존 게시판 E를 검사했다. 각 화면의 대비·최소 글자·잘림·버튼 가림·겹침 문제와 예상 밖 페이지·콘솔·자원·API 오류는 0이었다. 지도 버튼 보완 뒤 타입·CSS·관련 지도 테스트 13개·변경 파일 lint를 다시 확인했다. CI에는 이 UI 검사를 별도 작업으로 추가했다.

## CI 재시도 검사 보완

첫 CI의 FHD pending 캡처가 실제 12초 요청 제한 시간을 넘겼다. 처음 HTTP 전송만 잡던 하네스가 정상 재시도를 통과시켜 명시적 release 전에 도착한 것을 실패로 판정했다. 제품의 요청 제한 시간이나 재시도 동작은 수정하지 않는다. 하네스는 같은 requestId의 모든 전송을 한 gate에서 기다리고, 사용자 중복 선택 여부는 HTTP 전송 수가 아닌 고유 requestId/sequence로 판단한다.

지연시킨 네트워크 요청이 살아 있는 동안에는 비싼 화면 캡처를 기다리지 않고 pending DOM·입력 차단·같은 다섯 품질 지표·가로 넘침을 검사한 뒤 바로 해제한다. 정상·거절·도착 화면 캡처는 유지한다. 최종 기본 실행은 두 화면 12단계·12캡처와 pending DOM 측정 두 번으로 구성한다.

선택형 `--force-pending-retry --actors 7 --views fhd`는 실제 제한 시간까지 기다린다. 로컬 강제 재시도에서 같은 requestId/sequence가 12,031ms 간격으로 두 번 전송됐고, 둘 다 gate에 머물렀다. 해제 전 farm 위치·pending 버튼 차단을 유지하고 해제 후 village 정규 도착점으로 이동했으며, 남은 왕복·거절·게시판 흐름까지 6단계·6캡처를 통과했다.

보완 후 기본 두 화면도 12단계·12캡처·14회 UI 측정을 통과했다. 모든 다섯 품질 지표는 0, 가로 넘침 없음, 예상 밖 페이지·콘솔·자원·API 오류는 0이었다. 의도한 409 거절 두 건은 별도로 확인했다. 제품 파일 변경 없이 하네스 lint와 diff 검사도 통과했다.
