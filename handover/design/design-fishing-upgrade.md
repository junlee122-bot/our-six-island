## 2. 7명 실시간 브라우저 게임에 맞춘 원칙

- **짧은 판**: 던지기 → 입질 1.5~6초 → 손맛 3~12초. 한 마리 20초 안팎. 스타듀처럼 시간이 멈추지 않으니 한 판이 길면 안 됩니다. 미니게임 최대 45초.
- **서버 권위, 부담 없는 검증**: 서버는 월드 행에 씨앗·성향을 저장합니다. 비밀 서명이 필요 없습니다(클라이언트가 씨앗을 바꿔도 서버는 저장된 값으로 계산). 클라이언트는 "성공했다"를 보내지 않고 **입력 기록(누름/뗌 구간 길이)**만 보냅니다. 서버가 같은 정수 시뮬레이션을 돌려 결과를 냅니다.
- **부정행위 대응은 친구 게임 수준**: 입력 기록이 실제로 흐른 시간보다 길면 거절, 1틱(25ms)마다 바꾸는 사람이 못 할 입력은 거절, 결과 뒤에 입력이 더 붙어 있으면 거절. 씨앗을 알고 완벽한 입력을 계산하는 봇은 막지 않습니다(친구끼리 그럴 이유가 적고, 대회 상품도 작게 둡니다).
- **정수 시뮬레이션**: `Math.sin` 같은 엔진마다 끝자리가 다를 수 있는 계산은 쓰지 않습니다. 위치·속도는 정수, 난수는 `Math.imul` 기반 mulberry32. 브라우저(V8/SpiderMonkey/JSC)와 Edge(Deno)가 같은 결과를 냅니다.
- **저장 호환**: 새 상태는 `world.life.angling` 한 곳에만 둡니다. 없으면 빈 값으로 읽고, 옛 `cast`/`reel` 행동과 `me.fishing` 보기는 그대로 둡니다(배포 중 옛 클라이언트도 동작). 데이터 마이그레이션 없음.
- **공유 파일은 덧붙이기만**: 어종·아이템 정의는 `lounge-fish-data.ts`에 두고 `lounge-items.ts`는 배열에 펼쳐 넣기만 합니다. 엔진은 `lounge-fish-engine.ts`, 미니게임 계산은 `lounge-fish-minigame.ts`.

## 3. 어종

- 기존 46종 + 새 12종. 각 어종에 **성향**(느긋 `calm` / 쏜살 `dart` / 가라앉음 `sink` / 떠오름 `float` / 섞임 `mixed`)과 **난이도**(10~95)를 붙입니다(`FISH_PROFILE`). 난이도는 희귀도에서 기본값을 정하고 어종별로 손봅니다.
- **KST 시각 창**(`hours`): 뱀장어 20~4시, 오징어·한치 20~2시, 쏘가리 18~24시, 은어 9~17시, 금강모치 7~11시 등. 시각 창은 새 던지기에서만 쓰고, 옛 `fishCandidates`는 그대로입니다.
- **전설 5종**(친구마다 1번씩):

| 계절 | 이름 | 장소 | 조건 |
|---|---|---|---|
| 봄 | 벚꽃 산천어 | 폭포 소 | 맑은 날 06~10시, 낚시 Lv5, 낚싯대 3단 |
| 여름 | 호수의 주인 | 호숫가 선착장 | 비 오는 밤 22~03시, 낚시 Lv7, 낚싯대 3단 |
| 가을 | 달빛 갈치(기존) | 밤 항구 | 맑은 가을밤 |
| 겨울 | 겨울 왕대구 | 갯바위 | 새벽 05~08시, 낚시 Lv6, 낚싯대 2단 |
| 사계절 | 황금 잉어(기존) | 강 | 비 오는 날 |

- **바다 3종**: 숭어(바다·항구, 봄·겨울), 도루묵(바다, 겨울), 쥐치(갯바위, 여름·가을).
- **통발 6종**: 다슬기·민물새우(민물), 꽃게·바지락·굴·소라(바다). 낚싯대로는 안 잡힙니다.

## 4. 손맛 미니게임

틱 25ms(초당 40번), 막대 높이 단위 10,000.

| 값 | 기본 | 비고 |
|---|---|---|
| 초록 칸 높이 | 낚싯대 1~5단: 2,500 / 2,800 / 3,100 / 3,300 / 3,500 | 낚시 Lv마다 +50, 큰 찌 +700, 최대 4,600 |
| 칸 움직임 | 누르면 +9/틱, 떼면 −9/틱, 속도 ±200 | 바닥에 닿으면 약하게 튕김(속도 1/3) |
| 물고기 | 목표 지점을 정하고 쫓아감. 난이도가 높을수록 자주·빠르게 바꿈 | 성향별 목표 분포(가라앉음은 아래쪽, 떠오름은 위쪽, 쏜살은 순간 도약) |
| 게이지 | 시작 30%. 칸 안 +42/틱(빈 게이지에서 약 6초, 시작 30%에서 약 4.2초), 처음 0.5초는 줄지 않음, 밖 −(30 + 난이도/3)/틱 | 덫 찌: 줄어드는 속도 ×2/3 |
| 보물 상자 | 기본 12% + 보물 찌 15%p + Lv×0.5%p + 함께 낚시 친구당 2%p | 1~5초 사이에 나타남. 칸 안 +70/틱, 밖 −35/틱. 물고기보다 먼저 가득 차야 얻음 |
| 완벽 | 한 번도 칸 밖으로 안 나감 | 품질 +1, XP +50% |
| 최대 길이 | 1,800틱(45초) | 끝나지 않으면 놓친 것으로 처리 |

**흐름**: `anglerCast`(서버가 물고기·크기·입질 시각 결정, 숨김) → 찌가 잠기면 `anglerHook`(반응 등급 기록, 늦거나 이르면 놓침) → 서버가 **이 순간** 씨앗·성향·보물 여부를 저장하고 보기에 공개 → 클라이언트가 미니게임을 돌리고 입력을 구간 길이 배열로 압축 → `anglerLand`로 전송 → 서버 재시뮬레이션.

**챔질 여유(등급별, 2026-10-02)**: 입질 창(`windowMs` = 어종 창 × 낚싯대 배율 × 행운·성장·기분 배율, 그대로)이 닫힌 뒤에도 서버는 물고기 등급(`rarityOf`)에 따라 조금 더 챔질을 받아 줍니다. `expiresAt = biteAt + windowMs + HOOK_SLACK_MS[등급]`이고, 그 뒤에 온 챔질은 `late`로 놓칩니다. 여유는 네트워크·느린 화면 지연을 덮는 몫이라 흔한 물고기일수록 너그럽고 전설일수록 엄격합니다. 반응 등급(S~E, `reactionGrade`)은 입질부터 서버에 닿기까지 시간 그대로라서 여유 안에서 걸어도 창을 넘기면 E입니다. 옛 `cast`/`reel` 흐름은 하나뿐인 `REEL_SLACK_MS`(1.5초)를 그대로 씁니다.

| 등급 | 어종 창(1단) | 챔질 여유 `HOOK_SLACK_MS` | 입질부터 받아 주는 시간(1단) | 검증 스크립트가 참는 늦은 놓침 |
|---|---|---|---|---|
| 흔함 (weight ≥ 20) | 0.8~1.2초 | 3.0초 | 3.8~4.2초 | 3번 |
| 보통 (10~19) | 0.7~1.0초 | 2.2초 | 2.9~3.2초 | 2번 |
| 드묾 (2~9) | 0.55~0.65초 | 1.5초 (예전 모두 이 값) | 2.05~2.15초 | 1번 |
| 전설 (≤ 1) | 0.45초 | 1.0초 | 1.45초 | 0번 (바로 실패) |

- `scripts/verify-village-life-ui.mjs`의 `fishing-reel-fight`는 찌가 잠길 때 모의 서버 상태에서 숨은 물고기 등급을 읽고, 늦은 놓침이 쌓인 수가 그 등급의 허용치(`LATE_MISSES`)를 넘으면 실패합니다. 이른 놓침은 등급과 상관없이 바로 실패합니다.
- 보기의 `expiresAt − biteAt − windowMs`로 등급을 짐작할 수 있습니다. 어종은 여전히 숨기고, 등급 정도는 드러나도 괜찮다고 보았습니다.

**낚시 중 3D 화면 줄이기(2026-10-02)**: 낚시 창이 열려 있는 동안 뒤의 마을(`lounge-village.tsx`)과 구역(`lounge-area-3d.tsx`, 항구 낚시터) 화면은 `app/lounge-fishing-frames.ts`의 `fishingFrameDue`가 허락한 프레임에만 갱신하고 그립니다(움직임·주민·그림·이름표 갱신도 같이 쉼). 창이 낚시꾼과 찌를 가리므로 눈에 띄는 차이는 없습니다.

- 한 프레임 그리는 비용은 그린 직후 다음 애니메이션 프레임까지의 간격에서 화면 한 프레임(16.7ms)을 뺀 값(`FrameCost`, 지수 평균)입니다. WebGL은 화면에 낼 때 몰아서 그리므로 `renderer.render` 자체 시간(몇 ms)으로는 알 수 없습니다.
- 빠른 GPU: 최대 초당 약 30프레임(`FISHING_FRAME_MS` 33ms). 입질·챔질·손맛 단계도 그대로 그립니다.
- 느린 GPU(한 프레임 50ms 넘음): 그리는 시간이 전체의 12%(`FISHING_DRAW_SHARE`)를 넘지 않게 간격을 늘리고, 입질을 기다리는 중(`bite`)과 챔질 요청이 가는 중(`reeling`)에는 새 프레임을 시작하지 않습니다. 단계가 바뀌면(던짐·결과 등) 바로 한 번 그립니다.
- 헤드리스 Chromium(소프트웨어 WebGL, 1280×720, 낮음 품질, 30fps 제한)에서 `fishing-reel-fight` 3회씩 잰 값:

| 구간 | 전 | 후 |
|---|---|---|
| 낚시 전 마을 | 약 1fps, 프레임 900~970ms | 같음(낚시 창이 없을 때는 그대로) |
| 던지기 → 챔질 | 약 1fps, 긴 작업이 시간의 99~100% | 17~28fps(중간값 17ms), 긴 작업 2개(던짐·입질 대기 시작 때 한 번씩) |
| 챔질 반응(서버가 잰 입질 → 챔질) | 2,151~2,778ms | 9~11ms |
| 손맛 겨루기(0.7초 누르기) | 약 1fps, 100% | 60fps, 긴 작업 0 |

**거절 규칙**(시험 있음): 입력 합계 틱 × 25ms가 `hook 뒤 흐른 시간 + 2초`보다 김 / 1,800틱 초과 / 구간이 600개 초과 / 평균 구간 2틱 미만 / 결과가 난 틱 뒤에 입력이 1틱 넘게 더 있음 / 숫자가 아닌 값. 거절되면 놓친 것으로 기록(보상 없음).

## 5. 미끼·찌·낚싯대

## 6. 보물 상자 내용

## 7. 품질·판매·요리

- 품질: 크기 백분위 ≥ 60% 은별, ≥ 90% 금별, 완벽하면 한 단계 위(최대 금별). 저장은 `angling.u[uid].fq[id] = [은, 금]`이고 가방 개수를 넘으면 잘라 읽습니다.
- 판매: 기존 `sellItem`이 물고기를 팔 때 **좋은 품질부터** 팔고 가격에 품질 배율(1.25/1.5)을 곱합니다(`lounge-life-plus.ts`에 한 줄 훅). 요리·선물로 쓰면 보통 품질부터 빠집니다.
- 요리 5종(요리 탭에 자동 추가, 매운탕·해물탕·생선구이는 원래 있음): 모둠 회(물고기 2, 행운 효과), 해물파전(바지락 2 + 감자), 굴전(굴 2 + 감자), 꽃게탕(꽃게 + 감자 + 물고기), 다슬기국(다슬기 3 + 당근). 판매가는 기존 규칙(재료값 ×1.25 + 100).

## 8. 기록·수첩

- 친구별: 어종마다 잡은 수, 최대 cm, 최대 무게(g), 최고 품질, 첫 낚은 날.
- 마을 기록판: 기존 `records`(최대 cm) 그대로 + 이번 주 대회 순위.
- 낚시 수첩(낚시 창에서 `J`/버튼): 도감 탭(못 본 어종은 실루엣과 힌트: 사는 곳은 보이고, 계절·시각·날씨는 한 번이라도 같은 낚시터에서 무언가를 낚아야 보임), 기록 탭, 대회 탭, 통발 탭.
- 무게: `15.5 × 체형 × (cm/10)³ g` (기존 표시식을 엔진으로 옮김).

## 9. 함께 낚시와 낚시 대회

- **함께 낚시**: 같은 낚시터에서 최근 90초 안에 던진 다른 친구 수(최대 3). 친구 1명당 크기 +3%, 보물 +2%p, 게이지 줄어드는 속도 −5%. 결과 카드에 "함께 낚은 친구" 표시.
- **주간 낚시 대회**(KST 월요일 00시 ~ 일요일 24시): 잡은 물고기마다 점수 = 희귀 점수(흔함 10 / 보통 20 / 드묾 40 / 전설 100) × (1 + 크기 백분위) × (완벽 1.2). 친구별 **상위 3마리 합계**가 대회 점수. 주가 바뀌면 지난주 1~3위를 `cupHistory`(최근 4주)에 남깁니다.
- 상품: 1위 5,000범 · 2위 3,000범 · 3위 1,500범, `cupClaim` 행동으로 본인이 받음(원장 `grantBeom` 경유, 주 1회). 세 명 이상 참가한 주만 상품이 있습니다.
- **어시장 상인 훅**: `anglingHooks` — `tournamentStandings(life, week)`, `tournamentResult(life, week)`, `villageFishTotal(life)`(항구 구역 열림 조건 "마을 공동 낚시 합계"), `dawnAuctionBonus`(새벽 경매용 자리, 지금은 0). NPC 코드는 넣지 않았습니다.

## 10. 경제: 시간당 수익 비교

`node --experimental-strip-types --no-warnings scripts/fishing-economy.mjs`: 엔진 그대로 1시간을 낚고(던지기 → 챔질 → 기준 플레이어의 손맛 → 수거), 실제 판매 경로(수요 곡선·시장 포화·품질)로 판 값입니다. 기준 플레이어는 반응 175ms의 평범한 사람 흉내이고, 한 마리마다 휘두르기·반응·결과 읽기 3.9초를 더합니다.

| 활동(한 친구, 그날 첫 판매) | 시도 / 낚음 | 판매 |
|---|---|---|
| 강 · 봄 낮 · 낚싯대 1단 | 224 / 216 | 약 1.5만 범 |
| 연못 · 여름 낮 · 1단 | 214 / 193 | 약 1.5만 범 |
| 갯바위 · 가을 낮 · 3단 · 새우 미끼 · Lv6 | 226 / 213 | 3.4만 (미끼 1.8만 빼면 1.6만) |
| 밤 항구 · 가을 22시 · 3단 · Lv6 | 242 / 238 | 약 3.1만 범 |
| 바다 데크 · 겨울 낮 · 4단 · Lv10 · 잘하는 친구 | 288 / 287 | 약 4.4만 범 |
| (업그레이드 전) 강 · 봄 낮 · 1단 | 453 / 453 | 약 2.0만 범 |
| 농사 12칸(호박 / 딸기 / 수박) | — | 시간당 5,200 / 5,250 / 6,000범, 손 쓰는 시간 몇 분 |

- 새 흐름은 손맛 겨루기 시간만큼 한 시간에 낚는 수가 줄어서, 같은 자리 초반 수익이 **업그레이드 전보다 약 25% 낮습니다**. 품질 배율이 그 일부를 돌려줍니다. 낚시가 원래보다 돈을 더 찍어내지 않습니다.
- 성장한 친구(낚싯대 4단, Lv10)의 바다 낚시는 시간당 4만대이지만 하루 판매 한도 10만과 시장 포화(3만 이후 2만마다 반감)를 농사와 함께 나눠 씁니다. 농사는 손을 거의 안 쓰고 밭이 알아서 벌기 때문에 둘을 같이 하는 쪽이 이득입니다.
- 새로 생기는 범은 주간 대회 상품(주 최대 9,500범, 참가 3명 이상일 때)뿐입니다. 보물 상자·통발은 범을 주지 않습니다. 원장 불변식은 테스트가 매 행동마다 검사합니다.

## 13. 알려진 점

- 손맛 겨루기는 계속 누르고 떼는 조작이 필요합니다. 운동 기능이 불편한 친구를 위한 "쉬운 손맛"(칸 크게·게이지 천천히) 설정은 아직 없습니다.
- 소프트웨어 GPU 테스트 하니스(`npm run ui:shots`)에서는 모의 서버 왕복이 입질 창보다 길어져 겨루기 화면 캡처가 불안정합니다. 그래서 `--fishing-fight` 선택 옵션으로만 찍고, 겨루기 화면은 UI 키트(`?ui-kit` → 손맛 겨루기 탭)에서 서버 없이 확인할 수 있습니다.
- 옛 클라이언트의 `cast`/`reel`은 그대로 동작합니다(배포 중 섞여도 안전). 옛 흐름으로 낚은 물고기는 품질·기록장(`angling.u.log`)에 남지 않고 마을 최대어(`records`)와 개인 최고(`ext.best`)에만 남습니다.
- 서버가 이동을 막는 조건(`lounge-cloud-engine.ts`의 `ext.pending`)은 옛 던지기만 봅니다. 새 던지기 중 이동은 클라이언트가 막습니다. 필요하면 `anglingBusy()`를 같은 자리에 더하면 됩니다(공유 파일이라 이번에는 손대지 않음).
