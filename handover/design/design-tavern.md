## 1. 콘셉트와 분위기

### 1-1. 한 줄 콘셉트
> "밤 항구 옆, 허 선장의 허풍이 끝나지 않는 작은 주막. 오늘 밤 누가 제일 뻔뻔하게 속일까?"

- **주막 × 살롱**: 한국 주막(초가 처마, 주기 깃발, 옹기와 막걸리 통, 가마솥 국밥)에 서부 살롱의 요소(나무 바 카운터, 안장 의자, 현상수배 포스터, 다트판, 축음기)를 섞습니다. 둘 다 "여행자들이 모여 허풍을 떠는 곳"이라는 공통점이 있어 자연스럽게 어울립니다.
- **"살짝 수상하지만 따뜻함"**: 카지노(짙은 초록과 금색, 세련됨)와 회관(크림색, 밝음) 사이의 세 번째 색입니다. **짙은 호두나무, 호박색 등불, 검붉은 천, 놋쇠** 톤이고, 연기는 벽난로와 등불 주변의 옅은 안개 정도로만 씁니다. 공포나 누아르가 아니라, 동화 속 해적 주점에 가까운 톤입니다.
- **이름과 간판**
  - 건물 이름은 **허풍 주점**, 부제는 "허풍 카드 · 뻥총 룰렛", 게임 이름은 **허풍 카드**(두 번째 모드는 허풍 주사위)입니다. GAME_INFO 기호는 `뻥`입니다.
  - 간판은 판자에 캔버스 텍스처로 "허풍 주점"을 쓰고, 그 옆에 카드 두 장과 코르크 딱총을 그립니다. 입구 옆에는 흰 천에 "酒"자를 쓴 **주기** 깃대를 세웁니다(한국 주막의 상징). 밤에는 홍등과 한지 등이 켜집니다.
  - 입구의 A자 칠판(kArchive 메뉴판)에는 "오늘의 카드: ?"를 두어 호기심을 끕니다(항상 물음표. 실제 카드는 판마다 정해짐).

### 1-2. 호스트 NPC: **허 선장**(본명 허풍선)
- **설정**: 은퇴한 뱃사람이자 주점 주인입니다. "내가 말이야, 고래 등에 올라타서…" 같은 허풍이 입버릇이고, 그 허풍이 가게 이름이 되었습니다. 손님들의 허풍 대결을 보는 것을 제일 좋아합니다. 말투는 기존 호스트처럼 **해요체**로 짧고 다정하게 합니다. 가끔 "라고 내가 그랬지!"처럼 허풍 섞인 추임새를 넣습니다.
- **외형(우리 스프라이트 스타일)**
  - 치비 비율(머리가 몸의 1/3)입니다. 기존 두 호스트(젊은 여성)와 확실히 구분되도록 **둥글둥글한 중년 아저씨**로 합니다.
  - 흰 선장 모자(작은 닻 자수), 덥수룩한 적갈색 턱수염, 파랑·흰 줄무늬 세일러 셔츠, 짙은 갈색 조끼와 기다란 크림색 앞치마를 입힙니다.
  - 소품은 한 손에 놋쇠 주전자(막걸리)를 듭니다.
  - 무기는 들지 않습니다. 뻥총은 테이블 소품으로만 나옵니다.
- **포즈 6종**: 지금의 `HostPose` 순서(`calm, smile, deal, focus, wow, sorry`)를 그대로 따르므로 `lounge-host-sprites.ts`와 `lounge-interior-hosts.ts`를 고칠 필요가 거의 없습니다. `deal` 셀은 "카드를 테이블에 밀어 주는" 동작입니다(판 시작과 새 판 배분 때).
- **딜러가 필요한가?** **필요 없습니다.** 게임에 딜러의 선택이 없고 친구끼리만 겨룹니다. 카드 배분과 판정은 서버가 합니다. 허 선장은 루미·매화처럼 **테이블 끝에 서서 카드를 나누지 않습니다.** **바 카운터 뒤에 서서 진행 멘트와 표정만** 맡습니다.
  - 게임 화면에서는 기존 친구 게임들의 "진행 스트립" 자리에 허 선장의 둥근 얼굴 사진과 대사를 보여 줍니다(`DealerAvatar` 재사용).
  - 3D에서는 바 뒤 빌보드로 서 있고, 테이블 상태에 따라 `hostPose`가 그대로 표정을 바꿉니다.
- **그림 생성**: Higgsfield `gpt_image_2_5`(기존 호스트와 같은 모델), 3×2 시트, 마젠타 배경을 **1회** 생성합니다. 프롬프트는 부록 A에 있습니다.
  - 이번 설계 단계에서는 **생성하지 않았습니다.** 저장소 작업 규칙("유료 이미지 생성은 구조 작업 뒤에 계획적으로")에 따라 구현 2단계에서 한 번에 생성하기를 권장합니다.
  - 그림이 없는 동안에는 매화 시트를 갈색으로 틴트해 임시 호스트로 씁니다. 게임은 호스트 그림 없이도 완전히 동작합니다.

## 2. kArchive 에셋 계획

조사 방법
- `kcatalog.json`(6,691개)을 품목 계열별로 훑고(레스토랑·온천·공통 가구·명절·사계절 계열), 후보 90개의 썸네일로 시트 3장을 만들어 눈으로 확인했습니다.
- 핵심 24개는 GLB를 받아 바이트, 삼각형, 텍스처, 바운드를 쟀습니다(`tavern/glb/`, `tavern/glbm.py`).
- 이미 저장소에 있는 모델은 **재사용(추가 0 KB)**으로 표시했습니다.
- 페이지 주소는 `https://karchive.vibeline.co.kr/models/<slug>`, GLB 주소는 `https://karchive-assets.vibeline.co.kr/models/v1/<컬렉션>/<slug>.glb`입니다.
- 약관(2026-09-25·26 기록과 같음): 사용·수정 가능, 원본 재판매 금지, **출처 표기 필수 "자료: kArchive / 출처: 쓰레드 dogfooter"**, CC 라이선스 아님. 새로 받는 모델은 `public/models/lounge/tavern/assets.json`에 URL, SHA-256, 바이트, 다운로드일, 약관 원문을 기록하고, `ATTRIBUTION.md`와 화면 크레딧에 추가합니다.

공통 특성(이번 실측으로 다시 확인)
- 모두 **메시 1개 · 머티리얼 1개 · JPEG 1024² 1장**이고 원점이 바닥입니다.
- 명절 계열(`christmas-*`, `newyear-*`, `dongji-*`)은 **가장 긴 변이 2 단위로 정규화**되어 있어 로더에서 목표 크기로 줄여야 합니다.
- 웹용 사본은 기존 파이프라인(`optimize-assets.mjs`: 양자화 + WebP)을 거치면 약 0.6~0.65배가 됩니다. 화면에서 작게 보이는 소품은 `textureMax: 512`로 줄여 개당 약 130~200 KB를 목표로 합니다.

## 5. 게임 설계: **허풍 카드**(Liar's Deck 규칙을 우리 식으로)

### 5-1. 인원, 덱, 배분
- **인원 2~4명, 기본 4명**(`SEAT_RANGE.liarsbar = [2, 4]`). 원작과 참고 저장소는 4명 고정입니다.
  - 20장 덱은 5명 이상이면 부족하고(5×5 = 25), 덱을 늘리면 확률이 바뀌어 원작 감각이 사라집니다. 그래서 5~7명은 **지원하지 않습니다.**
  - 7명이 모이면 두 판으로 나누거나, 3단계의 허풍 주사위 테이블(2~6명)을 씁니다.
- **덱 20장: K 6 · Q 6 · A 6 · 조커 2.** 조커는 **어떤 오늘의 카드로도 인정**됩니다(와일드).
- **판**(= 방아쇠 한 번으로 끝나는 단위) 시작 때마다
  1. 덱을 새로 섞어 **살아 있는 사람에게 5장씩** 나눕니다. 남는 카드는 아무도 보지 못하고 버립니다.
  2. **오늘의 카드**를 K, Q, A 중 하나로 균등하게 뽑습니다(crypto RNG, `cryptoPick` 재사용). 참고 저장소는 "직전에 진짜로 드러난 카드 종류"를 다음 오늘의 카드로 쓰지만, 이것은 예측을 돕는 부작용이 있어 **매 판 무작위**로 합니다.
- **첫 판 선**: 좌석 0부터 시작하고, 같은 친구들과 다시 할 때마다 한 자리씩 돌립니다(기존 `first` 회전과 같음). **다음 판 선**: 방아쇠를 당긴 사람이 살아 있으면 그 사람, 뻗었으면 그다음 살아 있는 사람입니다.

### 5-2. 차례
- 내 차례에 할 수 있는 것
  1. **내기**: 손패에서 **1~3장**을 뒷면으로 냅니다. 이것은 "전부 오늘의 카드(또는 조커)"라는 주장이며, 장수는 모두에게 공개됩니다.
  2. **거짓말!**: 바로 앞 사람이 낸 카드를 뒤집습니다(앞 사람의 내기가 있을 때만).
- 원작처럼 **바로 앞 사람만** 지목할 수 있습니다. 내가 카드를 내면 앞 사람의 주장은 그대로 넘어갑니다(암묵적 수용).
- **손패가 0장인 사람은 차례를 건너뜁니다.** 다만 누군가 거짓말을 외칠 때까지 판은 계속됩니다.
- **강제 지목**: 내 차례에 앞 사람의 내기가 있고 **나 말고 살아 있는 모든 사람의 손패가 0장**이면, 나는 **거짓말!만** 할 수 있습니다(내기 버튼 비활성). 이렇게 하면 판이 반드시 방아쇠로 끝나므로 참고 저장소의 "모두 0장이면 그냥 재배분" 같은 김빠지는 끝이 없습니다.
- **차례 시간 30초**(`TURN_LIMIT_MS.liarsbar = 30_000`). 시간이 지나면 자동으로 행동합니다(§5-8).

### 5-3. 거짓말! 판정과 공개 연출
- 뒤집은 카드 중 **오늘의 카드도 조커도 아닌 카드가 1장이라도 있으면 거짓말**입니다.
  - 거짓말이면 **낸 사람**이 방아쇠를 당깁니다.
  - 전부 진짜면 **지목한 사람**이 방아쇠를 당깁니다.
- 공개(phase `reveal`, 서버 고정 3.5초): 앞 사람이 낸 1~3장만 앞면으로 뒤집습니다. 그 판의 **이전 내기들은 끝까지 뒷면**입니다(원작과 같음. 정보가 새지 않음).
  - UI는 카드를 한 장씩 0.4초 간격으로 뒤집습니다. 진짜 카드에는 초록 테두리와 도장 "진짜", 가짜 카드에는 빨간 도장 "뻥"을 찍습니다.

### 5-4. 러시안룰렛: **원작 방식 그대로 유지**
- **모델(추천): 사람마다 권총 1자루, 6칸 약실에 실탄 1발, 판 시작(매치 시작) 때 실탄 위치 `chamber[seat] ∈ {0..5}`를 서버가 비밀로 정해 고정합니다.**
  - 방아쇠를 당길 때마다 `pulls[seat]`가 1 오르고, `pulls === chamber`인 순간 **뻥!**(탈락)입니다.
  - 같은 사람의 조건부 위험은 **1/6 → 1/5 → 1/4 → 1/3 → 1/2 → 1/1**로 오르고, 여섯 번째는 반드시 터집니다. 원작 *Liar's Bar*의 "돌리지 않는 리볼버"와 같습니다.
  - 당긴 횟수는 모두 공개합니다(원작도 "n/6"을 보여 줌). 그래서 "저 사람은 벌써 4번 당겼으니 지목을 조심하겠지" 같은 심리전이 생깁니다.
- **다른 두 모델과 비교(사장님 결정용)**

| 모델 | 탈락 확률(k번째 당김) | 느낌 | 판단 |
|---|---|---|---|
| **A. 고정 약실(원작)** | 1/6, 1/5, 1/4, 1/3, 1/2, 1 | 긴장이 오르고 최대 6번이 보장됨. 당긴 수가 전략 정보가 됨 | **추천. "그대로 유지"에 가장 맞음** |
| B. 참고 저장소식(위험도 k/6, 매번 독립) | 1/6, 2/6, … 6/6 | A와 비슷하게 오르지만 약실 개념이 없음(숫자 놀음) | 비추천 |
| C. 매번 실린더 회전 | 항상 1/6 | 긴장이 오르지 않음. 판이 길어짐 | 비추천 |

- **공정성 증명(추천, 작은 작업)**
  - 매치 시작 때 서버가 `commit[seat] = sha256(matchId|seat|chamber|salt)`를 공개하고, 매치가 끝나면 `chamber`와 `salt`를 공개합니다.
  - 결과 화면의 "탄창 확인" 버튼으로 누구나 해시를 다시 계산할 수 있습니다. "서버가 날 노렸다"는 친구 사이의 농담 섞인 의심을 없애 줍니다.
  - 구현은 Web Crypto `subtle.digest`(비동기)를 쓰지 않습니다. 방의 액션 처리는 동기이고, 기존 `lounge-crypto.ts`에도 비동기 함수(채널 암호화)만 있기 때문입니다. 대신 약 60줄짜리 동기 SHA-256 순수 모듈(`lounge-sha256.ts`)을 새로 두고 서버와 클라이언트가 공유합니다.
- **방아쇠는 본인이 직접 당깁니다**(phase `trigger`, 10초). 원작의 드라마를 살리는 핵심입니다.
  - "방아쇠 당기기" 버튼(Space/Enter)을 누르면 서버가 판정합니다.
  - 10초가 지나거나 자리 비움이면 서버가 대신 당깁니다(결과는 같음. 약실이 고정이라 시점이 결과를 바꾸지 않음).
- 결과(phase `shot`, 3초) 뒤 다음 판을 배분하거나 매치를 끝냅니다.

### 5-5. 탈락, 관전, 끝
- **뻗은 사람**: 자리에 그대로 남아 "뻗음" 상태가 됩니다. 얼굴은 회색 틴트에 검댕 자국과 유령 배지(lucide `ghost`)를 붙이고, 이름표는 "관전 중"으로 바뀝니다.
  - 채팅과 스티커는 계속 쓸 수 있지만, **보는 정보는 관전자와 같습니다**(다른 사람의 손패를 보지 못함. 음성 채팅으로 훈수하는 것을 막기 위함).
- **이김**: 살아 있는 사람이 1명이 되면 매치가 끝납니다. 동시 탈락은 규칙상 **불가능**합니다(방아쇠는 한 번에 한 사람). 그래서 **무승부가 없습니다.**
- **다시 하기**: 기존의 "retained 테이블 → 준비 확인(60초) → 같은 자리로 새 매치" 흐름을 그대로 씁니다(`READY_LIMIT_MS`). 새 매치마다 약실을 새로 장전하고 첫 선을 한 칸 돌립니다.
- **누적 기록**(라이어 게임의 `totals`처럼): 테이블에 연속으로 앉아 있는 동안 "우승 횟수 · 거짓말 적발 수 · 생존 당김 수"를 보여 줍니다.

### 5-6. 범 걸기(선택)
- **기본은 파티 판(0범)**이고, 테이블을 만들 때 **1,000 / 5,000 / 10,000범** 참가비 칩을 고를 수 있습니다. 5만 이상의 고액 칩은 **이 게임에서 열지 않습니다.** 탈락 연출과 큰돈이 겹치지 않게 하려는 톤 보호입니다.
- **최후 생존자가 판돈 전체(참가비 × 인원)를 가집니다.** 결과 배열은 `result[i] = (i === winner ? stake × (n−1) : −stake)`이고 합은 0입니다. 그래서 기존 `settleGame`의 "블랙잭 외에는 합이 0" 검사를 그대로 통과합니다.
- 흐름: 테이블 구성 → `reserveGame(ledger, id, 'liarsbar', wallets, deposits)` → 매치 종료 시 `settle('liarsbar', g)` → `settleGame(..., g.result)`. 야추와 **완전히 같은 경로**입니다. `EconomyGame`, `lounge-economy-report.ts` 라벨("허풍 카드"), `flowBucket`에 항목을 추가합니다.
- **봇은 범이 걸린 판에 앉을 수 없습니다.** 대타 봇과 연습 봇은 모두 파티·연습 판 전용입니다.
- 매치가 비정상 종료되면(방 재시작 시 스냅숏 복구 실패 등) 기존 `voidGame`으로 전액 환불합니다.

### 5-7. 연습 판과 봇
- **연습 판**(`PRACTICE_GAMES`에 추가): 나 + 봇 3명, 범 없음. 이름은 `PRACTICE_NAMES.liarsbar = ['루미', '매화', '무쇠']`(마을 NPC 카메오)로 합니다. `SOLO_TABLES`에 "허 선장네 연습 판 · 허풍 주점 · 봇 셋과 · 범 없이"를 추가합니다.
- **대타 봇**: 파티 판에서 2~3명만 모였을 때 테이블 시트에서 "빈자리 봇으로 채우기"를 켤 수 있습니다(4인 느낌 유지).
- **봇은 반드시 "자기 자리의 공개 뷰"만 입력으로 받습니다**(`liarsBarBot(view: LiarsBarView)`). 서버 내부 상태를 넘기지 않으므로 치팅이 구조적으로 불가능하고, 테스트로 보장합니다(§7-5).
- **판단 규칙**(난이도 "보통". 연습 판에서 "쉬움/보통" 선택)
  - **지목 판단**
    1. 강제 지목이면 지목합니다.
    2. 확정 판단: 내 손의 진짜 카드(오늘의 카드 + 조커) 수를 `m`이라 할 때, 앞 사람이 낸 장수 `k > 8 − m − (이번 판에 이미 공개된 진짜 수)`이면 **확실한 거짓말이므로 지목**합니다.
    3. 확률 판단: 초기하분포 근사로 "앞 사람 손(공개 장수 h)에서 진짜가 k장 이상일 확률"을 계산하고 `P(거짓) = 1 − 그 확률`로 둡니다. 여기에 앞 사람의 과거 적발률을 ±0.1 반영합니다.
    4. 임계값은 0.55를 기본으로 하되, **내 당긴 수가 많을수록 +0.05씩 신중**해지고(틀리면 내가 당겨야 하므로), **앞 사람의 당긴 수가 많을수록 −0.03**(상대가 궁지)으로 조정합니다. 약간의 무작위(±0.08)를 넣어 읽히지 않게 합니다.
  - **내기 판단**
    1. 진짜 카드가 있으면 보통 1~2장을 진짜로 냅니다.
    2. 손에 진짜만 남았으면 최대 3장을 냅니다.
    3. 진짜가 없으면 1장으로 허풍을 칩니다. 다음 사람이 강제 지목이 될 상황이면 2장 이상 내지 않습니다.
    4. 쉬움 난이도는 허풍 확률 35%, 보통은 진짜와 가짜를 섞는 확률 15%입니다.
  - "쉬움"은 확률 판단 없이 k ≥ 3이거나 확정일 때만 지목합니다.
- 시뮬레이션(`sim.mjs`, 단순화한 봇 4명, 2만 판): 방아쇠 평균 11.8회, 차례 평균 64.6번, 지목 중 실제 거짓말 비율 48%(적당한 긴장)입니다. 사람 판(생각 시간 8초/차례 가정)은 **약 11분**입니다. 너무 길다는 피드백이 나오면 "빠른 판"(약실 4칸, 1/4 → 1/1) 옵션을 추가하되, 기본은 원작대로 6칸입니다.

### 5-8. 자리 비움, 연결 끊김, 시간 초과
- **시간 초과(30초)**: 서버가 **1장을 자동으로 냅니다.** 진짜 카드가 있으면 진짜 1장, 없으면 무작위 1장입니다. 강제 지목 상황이면 자동으로 지목합니다.
  - 참고 저장소의 "시간 초과 = 방아쇠 벌칙"은 친구끼리 하는 게임에서 네트워크 끊김이 곧 죽음이 되므로 **채택하지 않습니다.**
- **자리 비움(연결 끊김)**: 기존 `liarAway`와 같은 `liarsbarAway` 집합을 둡니다. 자리를 비운 사람의 차례에는 **3초 뒤 자동 행동**을 합니다(`hostedTick`의 away 가속 규칙). 방아쇠 phase는 2초 뒤 자동으로 당깁니다. 다시 접속하면 즉시 해제되고 손패를 그대로 보게 됩니다(스냅숏에 저장된 상태).
- **범 판 보호**: 같은 사람이 **자리 비움이나 시간 초과로 2번 연속** 자동 행동하면 **기권(탈락, 참가비는 판돈에 남음)**합니다. 자리를 비운 사람이 자동 플레이로 판돈을 가져가는 일을 막습니다.
  - 파티 판에서는 기권 대신 **대타 봇으로 바꿔서** 친구들이 계속하게 합니다(돌아오면 다음 판부터 복귀).
- **나가기(자발적)**: 매치 중 "나가기"는 확인 창을 띄운 뒤 기권으로 처리합니다. 파티 판이면 대타 봇이 앉습니다.
- 모든 사람이 끊기면 서버 스냅숏이 유지되고, 돌아오면 이어서 합니다(시간이 흐르므로 자동 행동으로 진행되었을 수 있음). 1시간 동안 사람이 아무도 없으면 매치를 무효로 하고 범을 환불합니다.

### 5-9. 숨긴 정보(서버 뷰 규칙). 절대 새면 안 되는 것
- 서버 전용 `LiarsBarMatch`에만 있는 비밀 값
  - `hands[seat]`(각자의 손패), `pending.cards`(뒷면으로 낸 카드의 실제 값), `pile`(이번 판에 낸 카드 전체), `chamber[]`, `salt[]`, 덱의 남은 카드
- `liarsBarView(g, seat)`가 돌려주는 것
  - **모두에게**: 인원, 이름 순서, 살아 있음 여부, `handCount[]`, `pulls[]`, `commit[]`, 오늘의 카드, 판·차례·phase, 이번 판 각 내기의 **(자리, 장수)** 기록, 마지막 공개(거짓말! 때 뒤집은 1~3장과 판정), 로그, 타이머 키
  - **내 자리만**: `hand`(내 카드 5장 이하의 실제 값), `legal`(`play`, `call`, `trigger`, 선택 가능한 카드)
  - **관전자와 뻗은 사람**: 위의 "모두에게"만
  - **매치가 끝난 뒤에만**: `chamber[]`, `salt[]`(증명용). 손패는 끝나도 공개하지 않습니다(필요 없음).
- 기존 방 구조와 똑같이, 매치는 방의 **비공개 스냅숏**(`HostedRoomSnapshot.liarsbar`)에만 있고 각 클라이언트는 자기 자리의 뷰만 받습니다(`lounge-room.ts`의 `liar` 처리와 같음).
- 테스트: 모든 자리와 관전자 뷰를 `JSON.stringify`해서 다른 사람의 카드 id, `chamber`, `salt`, `pending`의 실제 값이 **문자열로도 나타나지 않음**을 무작위 1,000판에 걸쳐 검사합니다.
- 카드 id는 판마다 **무작위 순번**으로 새로 매깁니다(`0..19`를 섞어 배정). id로 종류를 추측할 수 없게 하기 위함이며, 참고 저장소의 `king_hearts_1` 같은 의미 있는 id는 쓰지 않습니다.

### 5-10. 소소한 재미(선택)
- **이달의 허풍왕**: `recordTables`(`lounge-life-plus.ts`) 방식으로 월별 우승 수, 거짓말 성공(들키지 않은 허풍) 수, 적발 수를 집계합니다. 1등의 얼굴을 주점 뒷벽 현상수배 포스터에 걸어 줍니다.
- **안주(파티 아이템)**: `PARTY_GAMES`에 `liarsbar`를 넣어 파티 판에서 가방의 작물을 먹는 기존 연출을 그대로 씁니다(주점과 잘 어울림).

### 6-1. 카드 그림

### 6-3. 러시안룰렛 연출(무섭지 않게, 긴장감은 원작처럼)
- **순서**(서버 phase: `reveal` 3.5초 → `trigger` 최대 10초 → `shot` 3초)
  1. **공개**: 카드를 한 장씩 뒤집고 "진짜"/"뻥" 도장을 찍습니다. 허 선장이 `wow` 포즈를 합니다.
  2. **가운데 오버레이**: 화면이 어두워지며 **당사자의 좌석 카드가 1.15배로 밀려 들어오고**(게임 화면의 "카메라 푸시인"), 나머지 좌석은 흐려집니다. 3D 방의 관전자 화면에서는 정사영 줌이 걸립니다(§4-2).
  3. **뻥총이 테이블에서 미끄러져 옵니다**(SVG, 0.4초). 실린더에 **당긴 칸이 표시**됩니다. 당사자에게는 "방아쇠 당기기 (Space)" 버튼과 10초 링 타이머를 보여 주고, 다른 사람에게는 "매화 님이 방아쇠를 잡았어요…"를 보여 줍니다. 심장 박동 합성음이 1초에 1번 울립니다.
  4. 당기면 **실린더가 한 칸 딸깍 돌고(0.3초)** 1.0초 동안 멈칫합니다(허 선장 `focus`).
  5. **결과**
     - **살았다!**: "딸깍" 소리, 좌석 카드에 "살았다!" 도장과 식은땀 방울, 허 선장 `smile`, 탄창 ○가 ●로 바뀝니다.
     - **뻥!**: 코르크가 튀어나가는 "뻥!" 소리, **만화 연기와 색종이가 퍼지고**, 당사자 얼굴에 **검댕 자국과 부스스한 머리**(CSS 필터 + 오버레이 PNG 1장)가 생깁니다. 그다음 회색이 되며 유령 배지("뻗음 · 관전 중")를 붙입니다. 허 선장은 `sorry`입니다.
- **톤 가드**
  - 총구는 **절대 사람(머리)을 향하지 않습니다.** SVG 뻥총은 **천장을 향해 들고** 쏩니다. 탈락은 "뻥총이 터져 검댕을 뒤집어쓰고 기절"이라는 슬랩스틱 설정입니다.
  - 피, 쓰러진 몸, 총상 표현은 없습니다. "죽음" 대신 "뻗음", "탈락" 대신 "오늘은 여기까지" 같은 단어를 씁니다.
  - 원작처럼 머리에 겨누는 연출은 **넣지 않기를 권장**합니다. 사장님 결정 사항에 적어 둡니다.
- 설정의 "움직임 줄이기"(reduced motion)를 켜면 회전, 줌, 파티클 없이 결과 도장만 보여 줍니다.
- **3D 방(걸어 다니며 구경하는 사람)**: 테이블 가운데의 절차 생성 뻥총이 당사자 쪽으로 돌아갑니다. 결과가 "뻥"이면 당사자 의자 위에 연기 스프라이트(빌보드 4프레임)가 올라오고, 그 사람의 빌보드에 회색 틴트와 유령 배지를 씌웁니다. 허 선장 빌보드의 포즈도 바뀝니다.

### 6-4. 키보드(게임 화면 안에서만. 걷기 키와 충돌 없음)

| 심장 박동 | 합성(저역 사인파 60 Hz 두 박, 초당 1회) |
| 살았다(딸깍) | `select`(음높이 −3) |
| 뻥! | **합성 코르크 팝**(백색잡음 20 ms 버스트 + 사인파 420 → 90 Hz 스윕 120 ms) + 종이 소리(대역 통과 잡음) |
| 우승 | Kenney Music Jingles 피치카토 1개(`jingles_PIZZI` 계열, 반입은 4단계) |

- 새 파일은 우승 징글 1개(약 15 KB)뿐입니다. 나머지는 기존 `SFX_FILES`와 WebAudio 합성으로 해결합니다.
- 실내 환경음은 벽난로 장작 타는 소리(합성: 잡음 + 무작위 크랙 펄스, 실내 음악 아래 −30 dB)와 문 근처의 항구 파도(마을 쪽 소리를 낮춰 재사용)입니다.

### 6-8. 음악 슬롯 `tavern`
- `MusicPlace`에 `'tavern'`을 추가하고 `MUSIC_TRACKS.tavern = { files: ['/assets/lounge/music/tavern.ogg', '/assets/lounge/music/tavern.mp3'] }`를 둡니다. 빌드는 파일이 없으면 경로를 비우고, 비어 있으면 합성곡으로 대체합니다(기존 슬롯 규칙).
- **Suno 프롬프트 예시**: "cozy smoky harbor tavern, slow swing shuffle 88 bpm, upright bass, brushed snare, slightly out-of-tune honky-tonk piano, accordion, soft gayageum plucks as accents, warm, playful and a little mischievous, no vocals, seamless loop, 2:30"
- **합성 대체곡(`lounge-music-score.ts`의 `PIECES.tavern`)**: D 도리안, 셔플 8분음표, 88 bpm입니다.
  - 워킹 피치카토 베이스(카지노 베이스 음색 재사용)와 **디튠 피아노**(삼각파 2개를 ±6 cent로 겹침)로 반주합니다.
  - 아코디언 드론은 톱니파에 저역 통과 필터를 걸고 트레몰로 5 Hz를 줍니다.
  - 4마디마다 화음 진행은 Dm7 – G7 – Dm7 – A7입니다.
  - 음량 기준은 기존 `PIECE_LEVEL`을 따릅니다.
- 게임 중에는 기존 `GAME_MUSIC_LEVEL`(0.4) 규칙을 따르고, **룰렛 phase에서는 음악을 0.15까지 더 낮춰** 심장 박동이 들리게 합니다.

## 7. 기술 설계

### 7-1. 엔진 모듈 `app/lounge-liarsbar.ts`(순수 함수, 서버 권위, 새로 작성)

```ts
export type LbCard = 'K' | 'Q' | 'A' | 'J';          // J = 조커(와일드)
export type LbPhase = 'play' | 'reveal' | 'trigger' | 'shot' | 'over';
export type LbPlay = { seat: number; ids: number[] };          // ids: 이번 판 무작위 카드 id
export type LiarsBarMatch = {
  id: string; revision: number; n: number; first: number; stake: number;
  phase: LbPhase; round: number; turn: number;                 // turn: 행동할 자리(-1 없음)
  table: 'K' | 'Q' | 'A';
  cards: Record<number, LbCard>;                               // 비밀: 이번 판 id → 종류
  hands: number[][];                                           // 비밀
  plays: LbPlay[];                                             // 비밀(ids). 공개는 {seat, count}
  pending: number | null;                                      // plays의 마지막 인덱스(지목 대상)
  alive: boolean[]; pulls: number[];
  chamber: number[]; salt: string[]; commit: string[];         // chamber·salt 비밀(끝나면 공개)
  reveal: { caller: number; target: number; ids: number[]; faces: LbCard[]; lie: boolean } | null;
  shooter: number | null; lastShot: { seat: number; out: boolean } | null;
  idle: number[];                                              // 연속 자동 행동 수(범 판 기권 판정)
  winner: number | null; result: number[];                     // 정산(합 0)
  totals: { wins: number[]; caught: number[]; bluffs: number[] };
  log: { seat: number; text: string }[];
};
export type LiarsBarAction =
  | { kind: 'play'; ids: number[] } | { kind: 'call' } | { kind: 'trigger' } | { kind: 'forfeit' };
export type LiarsBarView = /* 공개 필드 */ {
  hand: { id: number; face: LbCard }[] | null;                 // 내 자리만
  handCount: number[]; plays: { seat: number; count: number }[];
  role: 'player' | 'out' | 'watcher';
  legal: { play: boolean; call: boolean; forced: boolean; trigger: boolean; max: number };
  chamber: number[] | null; salt: string[] | null;             // over에서만
  /* … phase, table, pulls, alive, commit, reveal, lastShot, winner, result, totals, log, turn, round */
};

export function newLiarsBar(id, n, stake = 0, first = 0, totals?, pick = cryptoPick): LiarsBarMatch;
export function liarsBarAction(g, seat, a): LiarsBarMatch;    // 불법이면 throw (방이 reject로 바꿈)
export function liarsBarAdvance(g): LiarsBarMatch;            // reveal→trigger, shot→다음 판/over (시간 기반)
export function liarsBarAuto(g, away: Set<number>, timeout: boolean): LiarsBarAction | null;
export function liarsBarKey(g): string | null;                // `${id}:${phase}:${round}:${turn}`
export function liarsBarLimit(g): number;                     // play 30s, reveal 3.5s, trigger 10s, shot 3s
export function liarsBarView(g, seat: number | null): LiarsBarView;
export function liarsBarBot(v: LiarsBarView, level: 'easy'|'normal', rnd: () => number): LiarsBarAction;
export function liarsBarSettlement(winner: number, n: number, stake: number): number[];
```

- 불변식은 모든 액션 뒤에 `assertLiarsBar(g)`로 검사합니다(테스트 전용이 아니라 서버에서도).
  - 카드 보존(손패 + plays + 버림 = 20)
  - 살아 있는 사람 ≥ 1
  - `pulls[i] ≤ chamber[i]`(살아 있으면 `<`)
  - `result` 합 0
- **서버 시간 진행**: `reveal`과 `shot`은 사람 입력 없이 넘어가는 phase입니다. 방의 기존 턴 타이머(`timing(kind)` / `hostedTick`)가 `liarsBarKey`/`liarsBarLimit`으로 만료를 감지하면 `liarsBarAdvance`를 부릅니다. 라이어 게임의 phase 시계와 같은 구조입니다.

### 7-4. 스냅숏과 월드 크기 영향
- **방 스냅숏**: 4인 매치 JSON은 약 **1.2~1.8 KB**입니다(카드 20개, 기록 16줄, 해시 4개 × 64자). 기존 게임들(포커 ~2 KB)과 같은 수준입니다. 각 클라이언트가 받는 뷰는 약 1 KB입니다.
- **다운로드**
  - 마을 청크: 외관 GLB 약 0.54 MB(+간판 캔버스 0 KB)가 늘어납니다.
  - 주점 입장 시 지연 로딩: 실내 GLB 약 1.8~2.6 MB, 호스트 시트 WebP 약 0.25~0.35 MB, 음악 파일(있으면) 약 1.5~2.5 MB입니다.
  - 게임 청크(`lounge-liarsbar-table`)는 약 25~35 KB(gzip)로 예상합니다.
- **GPU 메모리**: 주점 안에서 약 20~26 MB(§2)이고, 나가면 기존 실내 dispose 규칙으로 해제합니다.
- **삼각형**: 실내 소품 약 16종(반복 포함 약 30개) × 평균 5k ≈ 15만입니다. 회관(카드 테이블, 의자 × 좌석 수, 옹기 등)과 비슷합니다. 병·잔·전구 줄처럼 같은 모델을 여러 번 놓는 것은 `InstancedMesh`로 처리합니다.
