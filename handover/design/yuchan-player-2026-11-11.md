# 여덟 번째 플레이어 유찬

유찬은 자율 행동 NPC가 아니라 승준·호현과 같은 고정 사용자 계정이다. actor는 마지막에 `7`, 계정명은 `yuchan`으로 추가한다. 기존 actor `0..6`과 계정 식별자, 저장, 집·밭 좌표는 유지한다. 게임별 최대 참가 인원과 요일 등 사용자 수와 무관한 숫자는 바꾸지 않는다.

## 그림과 움직임

사용자가 제공한 사진은 검은 머리·표정·흰 운동복의 특징을 참고하는 용도로 사용했다. 스타일 기준은 기존 `club-friends-classic.webp`이다. Higgsfield `gpt_image_2_6`에서 같은 비율·선·채색의 전신 그림을 만들었다. 원본 개인 사진은 이 저장소에 포함하지 않는다.

전용 `yuchan-atlas.webp`의 앞 다섯 칸은 기본 운동복, 주말복, 약속복, 아카츠키, 메이드다. 여섯째는 예비 표정이며 현재 의상으로 사용하지 않는다. 기존 친구 시트의 빈 칸이나 다른 친구의 얼굴로 대체하지 않는다.

게임의 공통 400×480 정규화, 발 기준선, 머리색·피부색·안경 처리와 2D 컷아웃 걷기·달리기를 재사용한다. 의상마다 별도 리그 다섯 개를 생성한다. 망토와 치마는 몸통을 함께 유지하고 아래 다리만 움직인다. 로그인 그림은 같은 440×540 투명 캔버스로 준비한다.

생성 기록과 프롬프트: `public/assets/lounge/yuchan-generation.json`, `yuchan-atlas.prompt.txt`. `node scripts/build-yuchan-assets.mjs`로 무손실 WebP와 로그인 그림을 재생성하고, `node --experimental-strip-types scripts/build-lounge-rig.mjs`로 리그를 재생성한다.

## 공간과 저장 호환

기존 일곱 집의 중심 좌표를 그대로 두고 동쪽 x=54.4에 새 집·밭·개인 부지를 붙인다. 농장 폭은 128로 넓힌다. 기존 부지·길·공동 시설과 겹치지 않는지 회귀 검사한다. 옛 일곱 칸 외형 저장은 그 칸을 그대로 읽고 여덟째 기본 외형만 채운다.

사용자 범위는 roster의 `ACTOR_COUNT`와 `isActor`를 기준으로 검사한다. 저장·생활·채팅·입장·방 방문·친구 응원·개인 부지·지도·우편·생일 방명록이 새 actor를 허용한다. 기존 일곱 명의 생일과 선물 취향은 보존하고, 유찬의 생일은 null과 미정 취향으로 둔다.

## 계정 준비

`supabase/migrations/20261111080731_add_yuchan_player.sql`은 기존 멤버 CHECK 범위와 명단을 확장하고 유찬 행 하나를 추가한다. 기존 계정·월드·지갑 저장을 초기화하지 않는다. Auth 계정은 공식 Auth Admin API로 생성한다.

`supabase/admin/provision-member.mjs`는 새 유찬만 준비할 수 있다. 이미 연결되거나 활성화한 계정은 거부하고, Auth 반환 이메일을 명단과 대조한 뒤 service_role 전용 `hh_provision_member`로 연결한다. 활성화 코드는 새 로컬 파일에만 쓰며 공개 저장소나 stdout에 출력하지 않는다. 신규 사용자가 첫 로그인에서 직접 비밀번호를 정한다. 코드 유효기간은 일주일이다.

운영 적용: 2026-11-11에 명단과 Auth 연동을 확인했다. 일회성 유찬 전용 작업 함수는 작업 후 HTTP 410만 반환하도록 폐쇄했고 실제 응답으로 확인했다. 활성화 코드는 비공개 로컬 안내 파일로만 전달한다. 기존 멤버의 활성 상태는 그대로다.

## 검증

새 저장과 옛 일곱 명 저장 보존, 잘못된 actor 경계, 여덟 명 동시 마을 입장·재입장과 원장, 농장 출입·부지 충돌, 코스튬별 그림·리그·로그인 배경 투명도를 검사한다. 브라우저 검증은 실제 계정과 외부 네트워크를 쓰지 않는 모의 월드에서 수행한다.
