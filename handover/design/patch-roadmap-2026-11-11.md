# 범타듀 밸리: 플레이 흐름 점검과 다음 기능 설계

작성: 2026-11-11. 기준: 원격 main `2cd8f5f`와 현재 게임 화면, 실제 엔진 코드. 아래 우선순위는 기획 판단이며 이용 통계를 측정한 결과는 아니다.

## 이번에 바꾸는 것

- 핫바 숫자키 자동 반복으로 음식이 소비되는 문제 수정. 새로 누른 두 번째 입력만 사용으로 처리한다.
- 침대 앞 행동을 ‘침대 사용’으로 표시. 실제 하루 마감의 밤·장소·횟수 검사는 유지한다.
- 연애 가능 주민 27명에게 단계별 선택 장면과 선택 기억의 후일담을 추가한다. 자세한 집필·검증 범위는 [연애 대사 확장 기록](romance-expansion-2026-11-11.md).
- 신규 플레이어 유찬은 별도 패치로 추가한다. 기존 일곱 명의 계정 식별자와 저장, 집·밭 위치를 유지한다.

## 이미 있는 기능을 다시 제안하지 않기

현재 게임에는 공동 밭·창고·시설 기금·공용 온실·계절 공동 목표·함께 먹기·친구 집 방문·방명록·추억 앨범·단체사진이 있다. 주민 29명 모두 선택 대화·기억·여섯 장 이야기가 있으며, 기술 재능과 명인 표지판도 있다. 농사·낚시·증권·카지노 종류를 더 나열하는 것보다, 이 콘텐츠를 찾고 이어서 즐기고 함께 마치는 흐름을 강화한다.

확인한 코드: `lounge-farm-sites.ts`, `lounge-npc-requests.ts`, `lounge-myday.ts`, `lounge-growth-data.ts`, `npc-talk/types.ts`, `lounge-npc-talk.ts`, `lounge/Bonds.tsx`, `lounge/FarmWorks.tsx`.

## 설계 하나: 복귀 할 일판

### 11월 11일 구현

유찬 추가 뒤의 패치에서 설계 하나·둘을 구현했다. `lounge-return-board.ts`가 기존 서버 뷰에서 권한 있는 수확·완료 가공·이야기 조건·밀린 마감을 읽고, 마을 소식의 ‘돌아온 오늘’에서 관련 창과 길 안내를 연다. 메뉴에서도 다시 열 수 있다. 목록은 새 보상이나 별도 완료 저장을 만들지 않고 원래 상태를 따른다.

`lounge-craft-tracker.ts`는 요리·제작 가구·농장 설비·시설 보유·가공품을 최대 세 목표로 계산한다. 요리·만들기와 농장 화면에서 고정하거나 성장 수첩의 네 번째 ‘제작 목표’ 쪽에서 고른다. 수량은 최종 보유 목표이며, 새 목표는 현재 보유에 추가 제작 수량을 더해 시작한다. 시설은 해당 종류 한 곳 보유이며 특정 부지의 두 번째 건설이나 증축은 이 목표의 범위가 아니다.

목표는 `life.ext[uid].craftTargets`에 저장한다. 기존 JSON 저장을 확장하므로 DB 스키마 변경은 없다. `craftTarget` 액션의 `pin/remove/quantity`를 서버 현재 목록에 원자적으로 적용하여 다른 목표를 덮어쓰지 않는다. 빈 옛 저장을 읽을 수 있고 자기 목표만 뷰로 보낸다. 목표 편집 자체에는 재료·범 비용이 없다.

계산은 실제 제작의 품질·최저가 카테고리 소모·기술 할인·확정 묶음 증산을 따른다. 같은 재료를 여러 목표가 중복 사용하지 않게 나누고, 중간 제작의 잉여와 재귀 원재료를 추적한다. 공동 창고는 참고 수량이다. 가공 ETA는 실제 투입된 기계의 산출 수량·품질·완료 시각만 사용하며 이미 투입한 원재료를 다시 요구하지 않는다. 예상 확률 증산은 세지 않는다. 꿀의 꽃은 소비 재료로 추정하지 않는다. 공동 시설은 총 건설 예산을 보여 주며 기존 모금과 기부를 차감하지 않는다고 표시한다.

회귀 검사는 새 계정·기존 저장·계정 격리·동시 고정·수량 상한, 실제 요리/제작 엔진과의 소모 대조, 모든 품질·가공 수령 전후, 길의 통행과 실제 행동 거리, 두 화면 크기의 모의 플레이를 포함한다. 전체 UI strict 검사는 화면 크기별 두 작업으로 나눠 같은 기준을 병렬 검사한다.

첫 접속의 어제 소식 아래에 ‘돌아온 오늘’을 놓는다. ‘익은 작물 여섯 칸’, ‘포도 가공 완료’, ‘프리렌이 기다리는 이야기’, ‘밀린 마감 한 번’처럼 현재 서버 상태에서 확인한 일만 보여준다. 항목을 누르면 관련 창이나 길 안내가 열리고, 완료 여부는 원래 기능의 상태를 따른다.

새 일일 보상이나 접속 연속 보너스는 추가하지 않는다. 기존 휴식·따라잡기 XP, 우정 감소 보호, 목장 도우미와 밀린 하루 마감은 이미 있다. 목표는 접속 압박을 더하는 것이 아니라 돌아왔을 때 무엇부터 할지 알려주는 것이다.

완료 기준: 장기 미접속·새 계정·농사만 하는 계정에서 거짓 완료/만료 항목이 없고, 각 안내가 실제 장소와 기능으로 이어진다. 친구 소식과 개인 할 일이 섞이지 않는다.

## 설계 둘: 제작 재료 추적

가구·요리·시설 화면의 ‘목표로 고정’을 누르면 성장 수첩에 최대 세 개가 등록된다. 가공품은 원재료까지 한 단계씩 펼쳐 보고, 내 가방과 개인 저장소의 보유 수량을 표시한다. 공동 창고는 별도 수량으로 표시하고 개인 몫으로 계산하지 않는다.

첫 버전은 자동 구매·자동 생산·재료 예약 없이 안내만 제공한다. 동일한 재료가 여러 목표에 중복될 때 ‘모든 목표 합계’를 함께 표시한다. 실제 제작 성공 여부는 기존 서버 검사를 그대로 쓴다.

완료 기준: 제작 순환 참조 방지, 품질별 재료 규칙 일치, 가공 중 수량의 이중 계산 방지, 목표 제거가 보유 아이템에 영향을 주지 않음.

## 설계 셋: 공동 주문서

### 11월 11일 구현

메뉴의 ‘친구 공동 주문서’, 마을 게시판의 같은 탭, ‘돌아온 오늘’에서 연다. 한국 시간 월요일 0시를 기준으로 쉬움·보통·도전 한 장씩 제시한다. 처음 확정한 한 장을 그 주의 마을 주문으로 유지한다. 기본 작물·강과 연못의 물고기·병 가공품을 쓰는 주문 아홉 개를 세 주 주기로 돌린다. 도전 주문은 친구 중 한 명의 개인 농장에 병 가공기가 놓여 있어야 고를 수 있다.

담당은 품목당 한 명이며 자기 담당만 맡거나 놓을 수 있다. 납품 권한을 독점하지 않으므로 담당이 아닌 친구도 보탤 수 있다. 부분 납품과 전체 기여 합계, 최근 24건의 납품 기록을 구분해 보여 준다. 개인 보유는 실제 가방·개인 보관·가공품 저장을 읽으며 품질 조건을 만족하는 낮은 품질부터 쓴다. 공동 창고는 작물만 별도 선택·확인한 경우에 사용하고, 개인 물건이 모자라도 자동으로 빌려 오지 않는다.

`lounge-community-orders-data.ts`는 변경하지 않는 버전 식별자를 가진 주문 정의와 주간 후보를 분리한다. 저장 복원과 보상 수령은 전체 정의에서 읽으므로 다음 후보 순서를 바꾸어도 과거 주문을 잃지 않는다. `life.communityOrders.records`에 현재와 지난 세 주를 보존하며 DB 스키마 변경은 없다. 새 액션은 기존 revision CAS·요청 식별자·클라이언트 순번으로 한 번만 반영한다. 동시 납품은 실제 남은 양으로 줄여 차감하고 이미 완료했거나 주가 바뀐 주문에는 차감하지 않는다.

완료 시 참가 친구들을 추억 앨범에 남긴다. 실제 납품한 각 친구가 해당 주문의 기존 일반 장식 가구 한 개를 한 번씩 직접 받으며, 완료한 지난 세 주도 수령할 수 있다. 보관 한도에 걸리면 수령권을 유지한다. 주문 선택과 담당 변경에는 활동·경험치·돈 보상이 없다. 성공한 납품과 수령만 실제 활동일을 표시하여 미접속 보충 계산과 맞춘다. 새 경험치·돈·수익 배율은 추가하지 않는다.

검증은 두 친구의 마지막 수량 경쟁, 초과 제출·재시도·중복 수령·주차 전환, 개인/공동/가공 저장과 품질별 차감, 과거 주문 복원과 보관 한도, 유찬을 포함한 서로 다른 계정·두 화면 크기의 모의 플레이를 포함한다.

일주일에 하나의 마을 주문을 둔다. 예를 들어 수확물·가공품·물고기를 함께 준비하는 주문이다. 친구가 맡을 품목을 표시할 수 있지만 맡지 않아도 납품할 수 있다. 한 번에 전량을 모을 필요 없이 일부씩 납품하고, 누가 무엇을 보탰는지 기록한다. 동시 접속은 필요하지 않다.

서버 상태는 주차, 주문 식별자, 요구량, 누적 납품량, 참가자 기여, 완료/보상 수령 기록으로 제한한다. 기존 월드 revision CAS와 요청 식별자로 중복 납품·이중 보상을 막는다. 공동 창고 사용은 확인한 경우에만 차감한다.

보상은 새 수익 배율보다 마을 장식·설계도·기념사진을 우선한다. 소수만 접속한 주에도 가능한 주문 규모가 필요하므로, 처음에는 난도가 다른 세 주문 중 친구들이 하나를 선택하게 한다.

완료 기준: 두 친구의 동시 부분 납품, 마지막 수량 초과 제출, 재접속·재시도, 주차 전환, 이미 완료된 주문의 이중 차감이 모두 안전하다.

## 설계 넷: 모임에서 협동요리로

모임은 기존 장소와 활동을 연결하는 얇은 기능으로 먼저 만든다. 게시판에서 활동·시각·장소를 정하고 참가/늦게 합류를 누른다. 친구 목록에는 진행 중인 모임과 위치가 보인다. 공개 채팅 자동 발송이나 외부 알림은 기본으로 켜지 않는다.

협동요리는 모임에 새 경험을 얹는 다음 단계다. 주점 큰 냄비에서 친구들이 재료 넣기·손질·불 조절을 나눠 맡아 약 한두 분 동안 한 음식을 만든다. 인원이 적으면 역할을 겸하고, 혼자도 더 천천히 완성할 수 있게 한다. 실패로 귀한 재료를 전부 잃는 구조는 피한다.

서버는 재료 차감, 역할 점유와 만료, 조리 단계, 완성 보상만 판정한다. 연출은 클라이언트가 담당한다. 완성물은 기존 함께 먹기 효과와 앨범에 연결하고 별도 현금 보상은 넣지 않는다.

완료 기준: 중간 이탈·접속 복귀·역할 교대·막판 합류를 지원하며, 매크로나 빠른 반복 입력으로 재료나 보상이 늘어나지 않는다.

## 연애 대사의 다음 단계

이번에는 모든 연애 대상의 일상 선택·관계 단계·기억 회상을 넓힌다. 그다음에는 인물별 사건을 작게 완성하는 편이 낫다. 처음 세 명을 골라 ‘서먹함 → 둘만의 약속 → 망설임 → 직접 마음을 표현함 → 선택을 기억한 후일담’의 사건을 각각 다르게 만든다.

사건에는 장소의 소품, 시선과 거리, 평소 말버릇이 잠깐 흐트러지는 순간이 있어야 한다. ‘좋아해’의 빈도만 늘리거나 모든 인물을 비슷한 상담 상대처럼 쓰지 않는다. 기다려 달라는 선택과 거절도 존중하고, 연애 상태가 아닌데 배우자처럼 말하는 대사는 조건 검사로 막는다. 기존 기혼 부부 신형만·봉미선의 설정은 유지한다.

## 유사 게임에서 참고한 경험

아래는 공식 소개에서 확인한 기능과 범타듀에 적용할 아이디어를 연결한 것이다. 해당 게임 전체의 품질을 수치로 평가하거나 범타듀가 그 기능을 그대로 복제해야 한다는 의미는 아니다.

- [Palia의 기술과 협동요리](https://www.palia.com/news/the-skills-of-palia): 생산의 결과를 같이 나누는 데서 한 걸음 더 나아가, 조리 과정의 역할을 함께 맡는 경험을 참고했다.
- [Palia의 사회 기능](https://support.palia.com/hc/en-us/articles/7475337549076-Social-Features): 친구를 찾고 합류하는 흐름을 모임 기능의 기준으로 삼았다.
- [Palia Home Tours](https://palia.com/news/patch-182): 기존 집 방문·방명록을 주제별 방 전시와 좋은 점 한 줄 남기기로 발전시킬 수 있다. 인기 순위보다 각자의 장점을 기록하는 방식이 소규모 친구 마을에 맞는다.
- [Nintendo의 Animal Crossing 꾸미기 안내](https://play.nintendo.com/news-tips/tips-tricks/animal-crossing-new-horizons-discover-tips/)와 [Dinkum 공식 소개](https://dinkum.krafton.com/en): 공간을 직접 바꾸는 경험을 공용 쉼터 한 곳으로 작게 적용한다. 마을 전체 지형 편집은 첫 범위에서 제외한다.
- [Stardew Valley 1.6 공식 변경 기록](https://www.stardewvalley.net/stardew-valley-1-6-update-full-changelog/): 숙련 이후에는 단순 수익 증가보다 플레이 방식이 다른 선택 과제와 기념 보상이 필요하다는 판단의 참고 자료다.
- [WEBFISHING 개발사 소개](https://store.steampowered.com/app/3146520/WEBFISHING/): 기타·분필처럼 보상 없이도 친구끼리 갖고 노는 도구를 참고했다. 이후 모닥불 기타나 제한된 공용 그림판 중 하나만 먼저 시험할 수 있다.

## 패치 순서와 확인 방식

입력 오류와 연애 대사 확장, 유찬 추가는 서로 분리해 GitHub에 반영한다. 이후 제안 기능은 복귀 할 일판과 제작 추적부터 시작한다. 월드 데이터를 바꾸는 공동 주문·협동요리는 서버 원장·멱등성·동시 접속 검증을 함께 완료한 뒤 배포한다.

문구와 대화 형식 검사는 전체 코퍼스를 대상으로 자동 실행하고, 감정선·인물 말투·설렘은 대표 장면을 직접 읽어 검수한다. 자동 검사가 문학적 몰입을 보장한다고 보고하지 않는다. 새 캐릭터는 로그인·코디·집·농장·이동·친구 표시와 옛 저장 호환을 한 흐름으로 확인한다.
