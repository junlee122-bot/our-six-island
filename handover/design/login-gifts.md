# 다음 로그인 선물

관리자가 비공개 world의 `loginGifts`에 예약한 선물만 처리한다. 클라이언트 요청이나 게임 액션으로 선물을 만들거나 금액·수령자를 고를 수 없다. 서버가 비밀번호를 확인한 `login` 성공 경로에만 `completeLoginGifts`를 연결한다. 자동 토큰 갱신, 활성화·복구, 게임 재접속·조회에는 지급하지 않는다.

지급은 기존 `hh_world_read` / `hh_world_commit` 비교 후 교환(CAS)으로 처리한다. `grantBeom`의 잔액·발행 합계·흐름 집계, 입금 완료 우편, 영구 수령 표식을 같은 world 저장에 담는다. 충돌하면 최신 world에서 재계산한다. 잔액을 바꾼 뒤 표식을 따로 쓰지 않는다.

예약 형식은 안정된 ID를 키로 `{ uid, amount, title, armedAt }`이며, UID는 서버 회원 표에서 확인한다. 처리 후 `deliveredAt`, `ledgerEntryId`를 같은 예약에 남긴다. 원장 최근 내역과 우편은 개수 제한으로 사라질 수 있지만 이 표식은 지우지 않는다. 같은 선물을 새 ID로 다시 등록해서도 안 된다. 원본 테스트는 합성 UID와 메모리 CAS 저장소만 사용한다.

운영 순서: 코드와 서버의 배포·검증 완료 → 해당 계정과 원장 불변식 확인 → world 행 잠금 안에서 중복 ID가 없는 경우에만 예약 추가 및 world revision 증가 → 예약 내용과 미지급 상태를 읽어 확인한다. 예약 자체는 원장과 잔액을 변경하지 않는다. 실제 수령 검증을 위해 사용자 계정으로 로그인하지 않는다.

2026-09-28 사용자 요청은 도원의 다음 로그인에 **200,000범**, 제목 **사장님 도박은 재미로만 하셔야 합니다**, 일회성이다. 이전 즉시 300,000범 요청은 이 요청으로 대체되었다. 실제 예약 여부는 배포 작업 기록에서 확인한다. 문서가 있다는 이유로 재등록하지 않는다.
