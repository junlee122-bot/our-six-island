# 텃밭 확장 설계 — 스타듀밸리 수준의 농사, 범타듀식으로

작성 2026-09-30 · 브랜치 `farming-upgrade` · 관련: `design-expansion-techtree.md`(기술·도구·연구), `design-mood.md`

이 문서는 지금 텃밭(작물 10종, 6/9/12칸, 물·비·비료·품질·온실)을 스타듀밸리와 비교하고, **친구 7명이 실제 시간으로 같이 노는 브라우저 게임**에 맞는 것만 골라 규칙과 숫자를 정합니다. 구현은 같은 브랜치에 있습니다(§9 파일 지도).

## 1. 한눈에

| 항목 | 결정 |
|---|---|
| 작물 | 10종 → **26종**. 새 16종은 모두 계절 작물(기본 4종은 그대로 사계절) |
| 다시 열림 | 8종(옥수수 + 새 7종). 계절이 끝나면 **시듦** |
| 지지대 작물 | 완두콩·오이·포도. 키가 커서 **같은 두둑 바로 뒤(북쪽) 칸에 그늘**(성장 10% 느림) |
| 거대 작물 | 호박·배추·수박. 한 두둑(3×2)을 같은 작물로 같이 심으면 익을 때 8% 확률로 합체, 칸마다 2개 |
| 자라는 모습 | 5단계(씨앗·새싹·잎·꽃/열매·수확). 흙은 마름/젖음/거름/보습 네 가지로 보임 |
| 밭 배치 | 마당 두 두둑 = **3×4 타일 격자**. 칸마다 흙(작물) 또는 설비(스프링클러·허수아비·벌통) 하나. 옮기기 가능. 옛 밭 칸 번호 = 타일 번호 |
| 가공 | 장독대 옆 **작업 마당 4자리**: 옹기(16h)·숙성통(24h)·건조기(8h)·씨앗 제조기(2h). 품질은 가공품으로 이어짐 |
| 품질 | 보통·은별·금별·**별빛**(×2). 별빛은 별빛 비료가 있어야 나옴 |
| 비료 | 비료·고급 비료 + **별빛 비료, 성장 촉진제, 보습 흙** |
| 까마귀 | 매일 새벽 5시, 작물 4칸 이상 자라는 밭에 30% 확률로 하나를 먹음. 허수아비 둘레 2칸은 안전 |
| 판매 | 기존 **바로 팔기(농협 창구)** + 새 **출하 상자**(KST 자정에 정산, 다음 날 시장의 첫 판매로 계산) |
| 친구 | 물 주기(기존) + **대신 거두기**(하루 한 집, 작물은 밭 주인 가방으로) |
| 품평회 | 매주 한 품목 출품(참가비 2,000범), 월요일 0시에 나세라 조합장이 심사. 상금 = 그 주 참가비의 50/30/20% |

## 2. 지금 텃밭 vs 스타듀밸리

| 스타듀밸리 | 지금 범타듀 | 이 작업 뒤 |
|---|---|---|
| 계절당 28일, 작물은 게임 날짜로 자람 | 계절 = 실제 7일, 작물은 실제 30분~12시간 | 그대로(실제 시간). 새 작물 1.5~24시간 |
| 작물 약 40종, 계절마다 8~10종 | 10종(사계절 4 + 계절 6) | 26종, 계절마다 9~14종 심을 수 있음 |
| 다시 열리는 작물(딸기·블루베리·옥수수…) | 옥수수 1종(3번) | 8종(3~5번) |
| 지지대 작물은 걸어서 못 지나감 | 없음 | 있음. 우리 두둑은 원래 못 걸어 들어가는 틀밭이라 "그늘"로 바꿈(§4-3) |
| 계절이 바뀌면 작물이 죽음 | 계절 밖 작물은 심지만 못 함 | 시듦(온실·온실지기는 예외) |
| 거대 작물 3×3 | 없음 | 두둑 한 판(3×2)으로 바꿈 |
| 매일 물 주기, 안 주면 안 자람 | 물은 "남은 시간 40% 단축" 보너스, 비 오면 자동 | 그대로 + 스프링클러 |
| 스프링클러 4/8/24칸 | 없음(연구 V8 "예정") | 기본/품질/별빛 = 4/8/24칸 |
| 허수아비·까마귀 | 장식 허수아비만 | 까마귀 사건 + 허수아비 설비 |
| 비료: 품질 3종, 속도 3종, 보습 3종 | 비료·고급 비료 | 5종(품질 3 + 성장 촉진제 + 보습 흙) |
| 품질 보통/은/금/이리듐 | 보통/은별/금별 | + 별빛 |
| 숙성통·병조림 등 가공 기계 | 요리·제작만 | 옹기·숙성통·건조기·씨앗 제조기·벌통 |
| 출하 상자, 밤에 한 번에 정산 | 바로 팔기(수요 곡선) | 둘 다 |
| 가을 축제 품평회 | 주간 축제 기금 | 주간 품평회(나세라 심사) |
| 농장 어디든 경작 | 고정된 6/9/12칸 | 타일 격자에 흙·설비를 자유롭게 |
| 친구 멀티: 같은 농장 | 친구 밭 물 주기(하루 한 집) | + 대신 거두기 |

## 3. 무엇을 골랐고 무엇을 뺐나

**고른 기준**: ① 실제 시간(시·일)으로 돌아가는 게임에서 "접속 안 한 동안"이 억울하지 않을 것, ② 서버 권위 순수 엔진으로 결정적으로 계산될 것(난수 없음, `hash32`), ③ 월드 한 행 JSON이 커지지 않을 것, ④ 원장 불변식과 경제 테스트를 깨지 않을 것, ⑤ 다른 에이전트가 고치는 마을 배치·NPC 파일을 거의 건드리지 않을 것.

- **실제 시간 유지**: 게임 속 "하루"를 새로 만들면 달력·날씨·축제·경제 테스트가 모두 흔들립니다. 작물은 지금처럼 시간 단위로 자라고, 하루 단위 사건(까마귀, 출하 정산, 시듦)은 **KST 날짜 경계**에 붙였습니다.
- **물 주기 규칙 유지**: 스타듀처럼 "안 주면 안 자람"으로 바꾸면 주말형 친구가 크게 손해봅니다. 물은 계속 보너스이고, 스프링클러의 가치는 "접속하지 않아도 물 준 상태로 자람"입니다(techtree §5-4와 같음).
- **밭 크기 유지, 배치 자유**: 마을 마당은 폭이 7~8.5m라 두둑 두 개가 꽉 찹니다. 마을 배치 파일(`lounge-village-layout.ts`)은 다른 작업이 고치는 중이라 두둑 틀과 충돌 판정은 그대로 두고, **두둑 안 12칸을 타일 격자로** 바꿨습니다. 칸마다 흙이나 설비를 고르고 옮길 수 있습니다. 가공 기계는 작물 칸을 뺏지 않게 **장독대 옆 작업 마당**(보행 판정 없는 장식 자리, 기존 옹기·장작과 같은 방식)에 둡니다. 격자 크기는 `GRID_COLS/ROWS` 데이터라 마당이 넓어지면 숫자만 바꾸면 됩니다.
- **지지대 = 그늘**: 스타듀의 지지대는 "길을 막아서 배치를 고민하게" 만드는 장치입니다. 우리 두둑은 원래 걸어 들어갈 수 없는 틀밭이라 막을 길이 없습니다. 대신 **같은 두둑의 바로 뒤 칸에 그늘**(그 칸에 새로 심는 작물 10% 느림)을 드리워, 지지대는 뒷줄에 두는 배치 고민을 만듭니다.
- **거대 작물 3×2**: 3×3은 12칸 밭의 3/4이고 두둑 사이 통로를 가로지릅니다. 두둑 한 판(3×2)을 단위로 합니다.
- **까마귀는 순하게**: 하루 최대 한 칸, 다 익은 작물은 건드리지 않음. 이미 저장된 밭에는 **소급하지 않습니다**(처음 정산하는 날부터 셈).
- **뺀 것**: 온실 건물 내부(마을 온실 공사 플래그로 대신), 과일나무 새 종류(과수원 언덕 V4 작업), 숙성 저장고(Cask), 광물·동물 가공(목장 V5), 게임 속 날씨 예보 변경.

### 4-2. 자라는 단계와 흙

- 화면용 5단계: 씨앗(0~25%) · 새싹 · 잎 · 꽃/풋열매 · 수확. 서버 판정용 `plotStage`(0~3)는 그대로 둬서 옛 화면도 맞습니다.
- 흙: **마름**(연갈색), **젖음**(물·비·스프링클러, 짙은 갈색), **거름**(비료 알갱이 점), **보습**(가장자리 이끼색). 시든 작물은 갈색으로 누워 있다가 다음에 밭을 만질 때 치워집니다.

### 4-3. 지지대 작물과 그늘

완두콩·오이·포도는 3D에서 나무 지지대에 올라갑니다. 같은 두둑에서 **바로 뒤(북쪽) 칸**에 새로 심는 작물은 그늘 때문에 10% 늦게 자랍니다(심는 순간 정해짐, 나중에 지지대를 뽑아도 소급 없음). 두둑 사이 통로 너머로는 그늘이 가지 않습니다.

### 4-4. 계절 끝의 시듦

계절 작물은 심은 뒤 처음 맞는 "그 작물의 철이 아닌 KST 날"의 0시에 시듭니다(추석처럼 계절을 고정하는 명절도 달력대로 따름). 사계절 작물, 마을 온실 공사(`greenhouse`)가 끝난 뒤, 농사 전문가 "온실지기"의 밭은 시들지 않습니다. 시든 칸은 수확물이 없고 다음 밭 행동 때 비워집니다.

### 4-5. 거대 작물

앞 두둑(0~5) 또는 뒤 두둑(6~11) 여섯 칸이 모두 **같은 거대 작물**이고 **같은 순간에 심었으면**(한 번에 심기), 다 익었을 때 `hash32(주인·두둑·심은 시각)`으로 8% 확률로 하나의 거대 작물이 됩니다. 한 칸만 거둬도 여섯 칸이 같이 거둬지고, 칸마다 2개(각 칸의 품질)가 나옵니다. 기대 수확량 +8%(해당 두둑만, 한꺼번에 팔면 수요 곡선 때문에 실제 수입은 더 적음).

### 4-6. 밭 타일 격자와 설비

```
북(집 쪽)   [6][7][8]    ← 뒤 두둑 뒷줄
            [9][10][11]  ← 뒤 두둑 앞줄
            ~~ 통로 ~~
            [0][1][2]    ← 앞 두둑 뒷줄
남(울타리)  [3][4][5]    ← 앞 두둑 앞줄
```

타일 번호 = 옛 밭 칸 번호입니다. 쓸 수 있는 칸은 밭 넓히기(6 → 9 → 12)로 늘어나는 그대로입니다. 비어 있는 칸에는 설비를 하나 놓을 수 있고, 설비가 있는 칸에는 심을 수 없습니다. 설비는 다른 빈 칸으로 **옮기거나** 가방으로 **거둘** 수 있습니다.

| 설비 | 조건 | 만들기 | 효과 |
|---|---|---|---|
| 스프링클러 | 농사 Lv6 | 3,000범 + 구리 4 + 돌 4 | 상하좌우 4칸 |
| 품질 스프링클러 | 농사 Lv8 | 10,000범 + 철 4 + 금 1 | 둘레 8칸, 물 효과 +5%p |
| 별빛 스프링클러 | 농사 Lv10 | 40,000범 + 금 6 + 보석 1 | 5×5(24칸), 물 효과 +10%p |
| 허수아비 | 없음 | 2,000범 + 나무 10 | 둘레 2칸 까마귀 막음 |
| 벌통 | 채집 Lv4 | 12,000범 + 나무 30 + 구리 2 | 16시간마다 꿀 |

- **스프링클러 동작**: 덮는 칸에 **심는 순간·다시 열리는 순간·스프링클러를 놓는 순간** 물을 준 것으로 기록합니다(`wateredAt`). 보기에서 계산하지 않고 사건 때 기록하므로 나중에 스프링클러를 옮겨도 이미 자란 시간이 바뀌지 않습니다. 원래 설계(techtree §5-4)는 연구 V8(기상 관측소)에 묶었지만 V8이 아직 준비 중이라, 농사 레벨만으로 열었습니다. V8이 열리면 레시피 할인을 붙이면 됩니다.
- **벌통**: 16시간마다 꿀 1병(쌓이지 않음). 거둘 때 둘레 2칸에 **다 핀 꽃**(튤립·백일홍·국화)이 있으면 가장 비싼 꽃의 꽃꿀(400 + 꽃값×2), 없으면 들꽃 꿀(400).

### 4-7. 까마귀와 허수아비

매일 KST 05:00에 밭마다 한 번 굴립니다: 그 시각에 **자라는 중인 작물이 4칸 이상**이면 30% 확률로, 허수아비 둘레 2칸 밖의 자라는 작물 하나를 먹습니다(다 익은 작물은 안전). 결정적(`hash32(주인·날짜)`)이고, 밭 주인이나 친구가 그 밭을 다음에 만질 때 정산됩니다. 저장된 밭은 처음 정산하는 날부터 셉니다(소급 없음). 먹힌 칸은 텃밭 장부의 "밭 소식"에 남습니다.

### 4-10. 출하 상자와 바로 팔기

- **바로 팔기(농협 창구)**: 기존 그대로(품목별 수요 곡선, 하루 3만 범 이후 점점 감소, 10만 범 안전 상한). 가공품도 같은 곡선(반감 4개, 인삼주 2개)을 탑니다.
- **출하 상자**: 작물(품질별)·과일·가공품을 넣어 두면 **KST 자정이 지나 처음 밭 주인이 무엇이든 할 때** 정산됩니다. 값은 **그날(정산하는 날) 시장의 첫 판매**로 계산하고 그날 수요에 더합니다. 그래서 같은 날 두 번 파는 차익은 없고(하루에 쓰는 수요는 하나), 수확이 많은 날 "내일 시장"으로 넘기는 기능입니다. 자정 전에는 도로 꺼낼 수 있습니다. 10만 범 상한을 넘는 몫은 상자에 남아 다음 날 팔립니다.
- 모든 범은 `grantBeom/spendBeom`만 지납니다.

### 4-11. 친구와 같이

- **물 주기**(기존): 하루 한 집, 우정 +5.
- **대신 거두기**(새): 하루 한 집, 친구 밭의 다 익은 작물을 모두 거둬 **친구 가방에** 넣습니다(품질·거대 작물·다시 열림 규칙 그대로). 나는 농사 XP와 우정 +5. 범은 움직이지 않습니다.
- 친구 밭에 들어가면 까마귀·시듦 정산이 먼저 됩니다.

### 4-12. 품평회 (매주, 나세라 조합장 심사)

- KST 한 주(월~일) 동안 한 사람이 한 품목(작물·과일·가공품, 품질 선택)을 출품합니다. 참가비 2,000범, 출품한 물건은 조합에 기증(돌려받지 않음).
- 점수 = 그 물건의 기본 판매가 × 품질 배수(철 작물 +10%, 가공품 +10%). 같은 점수는 먼저 낸 사람이 앞.
- 다음 주 월요일 0시 이후 누구든 무엇을 하면 심사가 정산됩니다: 1·2·3등에게 그 주 참가비 합계의 50/30/20%(10범 단위 내림). 상금 합계 ≤ 참가비 합계라 **범이 새로 생기지 않습니다**. 추억·마을 소식에 남고, 결과 4주치가 `life.fair.results`에 있습니다.
- **NPC 연결 지점**: `FAIR_JUDGE`(`app/lounge-farm-data.ts`: id `naseira`, 이름, 직함)와 `fairView(life, now)`(`app/lounge-farm.ts`: 이번 주 출품 목록, 지난 결과, 심사 시각). NPC 작업은 이 데이터로 나세라의 대사·위치를 붙이면 됩니다. 이 작업은 NPC 코드를 만들지 않습니다.

## 5. 경제

### 5-1. 원칙

1. **새 수입은 기존 판매 경로의 곡선을 탑니다.** 가공품·출하 상자 모두 품목별 수요 곡선과 하루 시장 포화(`marketMult`)를 거칩니다. 한 사람이 하루에 판매로 버는 양은 원래처럼 3만 범 이후 급격히 줄어(적분 상한 약 5.9만 범) 가공이 **천장을 올리지 않고, 같은 천장에 더 적은 작물로 닿게** 합니다.
2. **새 소비처가 새 수입보다 먼저 옵니다.** 설비·기계는 전부 범 + 재료가 들고(한 사람이 다 갖추면 약 18만 범 + 광석), 성장 촉진제·보습 흙은 소모품입니다.
3. **품평회는 순중립 이하.** 상금 ≤ 참가비.
4. **출하 상자는 차익이 없습니다.** 정산하는 날의 수요를 씁니다.
5. **씨앗 제조기**는 씨앗 구매를 줄이는(소비 감소) 기계라 가장 늦은 레벨(Lv9)에 두고, 평균 1.5봉으로 제한했습니다.

### 5-2. 한 사람이 다 갖추는 비용(소비처)

| 품목 | 수량 | 범 |
|---|---|---|

| 벌통 2 | 2 | 24,000 |

### 5-3. 인플레이션 점검

- 1년 7인 시뮬레이션(`tests/lounge-life-plus.test.mjs`)과 원장 불변식 검사는 그대로 통과합니다. 시뮬레이션 봇은 수박·배추 두둑을 통째로 심기 때문에 거대 작물의 영향이 그대로 드러납니다: 1년 뒤 범 총량 4,484만 → 4,684만(**+4.5%**). 거대 작물 확률을 12%로 두었을 때는 +7%여서 8%로 낮췄습니다. 까마귀·시듦은 반대로 조금 줄이는 쪽입니다.
- 가공 기계 4대를 모두 딸기 건조기로 돌리는 극단적인 경우도 하루 판매 수입은 시장 포화 곡선 때문에 위 5.9만 범 천장을 넘지 않습니다. 새 테스트 `tests/lounge-farm.test.mjs`가 "가공품을 대량으로 팔아도 하루 수입이 천장 안"과 "품평회 상금 ≤ 참가비"를 확인합니다.

## 6. 저장 형식과 옛 저장 이전

- `world.life.farms[uid]`(밭 칸 배열)은 **그대로**입니다. 타일 번호 = 칸 번호라 옛 밭은 옮길 필요가 없고, `readLife` 왕복이 같습니다(테스트).
- 새 필드는 모두 선택값이라 없으면 예전과 똑같이 읽힙니다.
  - 밭 칸(`Plot`): `fert` 3단계, `sg`(성장 촉진제), `rs`(보습 흙), `sl`(그늘 %).
  - `life.farmx[uid]`: `fx`(타일 → 설비 `{k, at, h?}`), `mach`(작업 마당 자리 → 기계 `{k, in?, q?, n?, at?, done?}`), `goods`(가공품 `id` 또는 `id@품질` → 개수), `bin`(출하 상자 `{day, items}`), `st`(까마귀 정산한 KST 날), `log`(밭 소식 최근 8개).
  - `life.fair`: `{week, entries: [{actor, uid, item, q, score, at}], results: [...]}`.
  - `ext[uid].q3`: 별빛 작물 개수(`q1`·`q2`와 같은 방식, `bag.produce`는 모든 품질의 합이라 옛 화면도 맞음).
- 모든 값은 읽을 때 범위를 자릅니다(설비 12개, 기계 4대, 가공품 종류 64, 상자 999개, 소식 8줄, 결과 4주).

## 7. 서버 행동과 보기

새 행동(`FARM_ACTION_KINDS`): `farmBuild`(설비·기계·별빛 비료 만들기), `farmPlace`, `farmPickup`, `farmMove`(설비 옮기기), `farmLoad`(기계에 넣기), `farmCollect`(기계·벌통 거두기, -1 = 전부), `ship`/`unship`, `sellGoods`, `harvestFriend`, `fairEnter`. 기존 `fertilize`는 새 비료 3종을 받습니다. 모든 행동은 먼저 밭을 정산합니다(까마귀·시듦·출하·품평회).

`lifeView`에 `farmx`(내 설비·기계·가공품·상자·소식·정산 예상), `fair`(품평회)를 더했고, 친구 밭 공개 정보(`housesPlotsPublic`)에 흙 상태·거대 작물·시듦을, `farmsPublic`에 친구 마당의 설비·기계 모양을 더했습니다(3D용, 작게).
