# 마을 2배 확장과 NPC 설계

작성 2026-09-30 · 상태: 설계안(코드 변경 없음) · 이후 작업: 주식 시스템(가게 NPC가 종목이 됨)

사용자 결정 사항
- 마을 면적을 **지금의 2배**로 넓힙니다.
- NPC 그림체는 **로제·그웬 체형**(일반 애니 체형, 약 6~7등신)으로 통일합니다.
- NPC 이름과 생김새는 **사용자가 레퍼런스를 줍니다.** 이 문서의 NPC 이름은 모두 자리 표시(역할명)입니다.

## 2. 마을 2배 확장

### 크기

96 × 76에서 **136 × 108**로 늘립니다. 가로와 세로를 각각 약 1.42배씩 늘려 면적을 2.0배로 만듭니다. 광장(0, 0)과 친구 집 줄, 강, 기존 구역의 좌표는 **그대로 둡니다.** 새 땅은 바깥 테두리에 붙습니다. 그래야 기존 저장 데이터(텃밭, 가구 배치, 낚시터)가 깨지지 않습니다.

### 기술 과제

| 과제 | 내용 |
|---|---|

| 이동 | 걸어서 끝에서 끝까지 1분이 넘으면 지루합니다. 구역마다 **이정표(빠른 이동)**를 두고, 한 번 가 본 구역만 열립니다 |
| 저장 데이터 | 기존 좌표를 그대로 두므로 이전 작업이 필요 없습니다. 새 구역 해금 여부만 생활 상태에 추가합니다 |
| UI 검사 | `ui:shots`에 새 구역 화면 추가, 기준(`scripts/ui-baseline.json`) 갱신 |

### 구역 해금

구역을 한 번에 다 열지 않습니다. 마을 공동 목표(기존 게시판 묶음·공공 프로젝트)로 하나씩 엽니다.

1. **시장 거리:** 처음부터 열립니다.
2. **항구 구역:** 마을 공동 기부 달성 시 열립니다(낚시 합계).
3. **언덕 주택가:** NPC 6명과 친해지면 열립니다(이사 이벤트).
4. **목장·과수원:** P3 연구를 마치면 열립니다.
5. **산기슭 마을:** 광산 10층에 도달하면 열립니다.

해금 순간이 곧 이벤트이고, 친구들이 함께 목표를 향하게 됩니다.

## 4. NPC 공통 시스템

### 일과표 (서버 저장 없음)

- NPC의 위치는 **KST 시각과 요일만으로 계산하는 순수 함수**입니다(`npcSpot(id, now)`).
- 서버 월드 행을 쓰지 않고, 실시간 채널로 보내지도 않습니다. 모든 친구 화면에서 같은 시각에 같은 위치에 있습니다.
- 예) 빵집 사장: 06~11시 가게 → 12시 광장 벤치 → 13~18시 가게 → 19~21시 허풍 주점 → 22시 이후 집.
- 비·축제·장날이면 다른 일과표를 씁니다(`lounge-calendar.ts`의 날씨·축제와 연결).
- 걷는 모습은 두 지점 사이를 보간해서 그립니다. 경로는 기존 `interiorPath`·걷기 충돌 함수를 재사용합니다.

### 관계

- `lounge-romance.ts`의 루미·매화 관계를 **모든 NPC로 일반화**합니다. 호감도, 하루 한 번 대화·선물, 선물 취향은 공통으로 두고, 데이트는 연애 가능 NPC에만 둡니다.
- 호감도 단계마다 보상이 있습니다: 할인, 레시피, 특별 의뢰, 집 방문.
- 누가 연애 가능한 NPC인지는 사용자가 정합니다(성인 NPC만 가능하고, 아이·할머니는 제외).
- **NPC끼리의 관계**는 데이터로 둡니다: 라이벌(빵집 ↔ 카페 메뉴 경쟁), 연인, 사제 같은 관계에서 이벤트가 나옵니다.

### 의뢰 게시판

- 기존 마을 게시판(`VILLAGE_BOARD`)을 확장합니다. NPC가 하루 2~3개 의뢰를 올립니다(배달, 수집, 낚시, 요리).
- 보상은 범·아이템·호감도입니다. 범은 새로 찍어 내는 보상(`granted`)이므로, 하루 상한을 경제 설계에 맞춥니다.
- 친구 여러 명이 같이 해결하면 보너스가 있습니다(협동 유도).

### 대사

- NPC마다 대사 파일을 둡니다(`lounge-friend-lines.ts` 형식). 인사·일과·날씨·호감도 단계·이벤트별 대사를 둡니다.
- 말투는 사용자 레퍼런스의 성격 설명을 따릅니다. `STYLE-AND-SOURCES.md`의 "AI티 금지" 규칙을 적용합니다.

## 5. 그림 규격

- **체형:** 로제·그웬과 같은 일반 애니 체형입니다. 딜러 루미·매화의 2등신과는 다르며, 루미·매화 교체 여부는 따로 정합니다.
- **시트:** 기존 호스트 시트와 같이 **3열 × 2행, 칸 440 × 660px**입니다. 발바닥은 648px 선, 서 있는 키는 600px(`HOST_CELL`).
- **포즈 6개:** 기본, 웃음, 일하는 동작(역할별), 생각, 놀람, 미안함. 마을을 걷는 NPC는 걷기 2프레임을 추가하면 좋습니다(시트 1장 추가).
- **초상:** 대화창용 머리·어깨 초상 1장(시트의 `HOST_PORTRAIT` 영역을 쓰거나 따로 생성)입니다.
- **배경:** 마젠타(#fb03fa 근처)로 만들고 실행 중에 제거합니다.
- **생성:** Higgsfield GPT Image 2.5를 쓰고, 로제·그웬 그림을 스타일 참조로 넣습니다. 프롬프트·작업 ID·SHA-256은 `generation.json`에 기록하고, `ASSETS.md`의 출처 표를 갱신합니다.
- **크레딧:** NPC 한 명에 시트 1장 + 걷기 1장 + 초상으로 약 3회 생성합니다(1회 약 2.75크레딧). **18명이면 약 150크레딧**이라, 단계별로 나눠 생성합니다.

## 7. 사용자에게 받을 것 (NPC별)

1단계 6명부터 받습니다.

| 항목 | 설명 |
|---|---|
| 이름 | 게임에 표시할 이름(예: "허 선장"처럼 호칭 포함 가능) |
| 생김새 레퍼런스 | 그림 1~3장. 머리·옷·분위기. 유명 캐릭터를 그대로 쓰면 IP 주의 표에 기록합니다 |
| 성격·말투 한 줄 | 예) "무뚝뚝하지만 단골에겐 덤을 주는 반말 사장님" |
| 나이대 | 성인·아이·노인 (연애 가능 여부 판단용) |
| 연애 가능 여부 | 성인 NPC만 가능 |
| (선택) 좋아하는 선물, 싫어하는 것 | 없으면 역할에 맞춰 초안을 씁니다 |
