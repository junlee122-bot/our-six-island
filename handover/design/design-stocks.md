# 범마을 증권 — 주식 투자 설계

작성 2026-10-02 · 상태: 설계 + 1차 구현(브랜치 `claude/stock-exchange`) · 앞선 맥락: [마을 확장 설계](design-village-2x-npcs.md) 3장 A “가게 주인 — 이후 주식 종목”, 신문 기자 “주식 소식”, 6장 4단계 “주식 시스템”.

시장 거리에 **범마을 증권**(증권사)을 열고, 마을 가게와 가상 회사의 주식을 사고팔게 합니다. 모든 돈 계산은 지금까지처럼 서버 권위 엔진(`app/lounge-stocks.ts`)에서 하고, 클라이언트는 결과만 그립니다.

---

## 1. 한 줄 요약

- 종목 12개: **마을 가게 9개**(친구들이 그 가게에서 실제로 사고판 거래액이 주가·배당에 반영) + **가상 테마주 3개**(변동성이 큼, 배당 없음).
- 장중(KST 09:00~15:30)만 주문. 시세는 **09:00부터 15:00까지 1시간마다 7번** 바뀌고, 하루 **±15% 상·하한가**.
- 시세 = 랜덤워크 + 가게 거래액·계절·날씨 + 뉴스 이벤트 + 친구들 주문의 작은 수급 효과. **서버에만 있는 비밀 씨앗**으로 결정적이라, 아무도 접속하지 않은 동안의 시세도 나중에 똑같이 계산됩니다.
- **현금 매수 · 신용 매수(최대 2배) · 공매도 · 환매수 · 신용 상환**. 안전장치(수수료, 신용 한도, 이자, 유지증거금·마진콜·반대매매, 대차 수수료, 손실 한도, 종목당 보유 한도, 시세 조종 방지)는 4장.
- 주간 배당(가게 종목, 지난주 거래액 기반), 친구 수익률 랭킹, 마을 소식(상·하한가·반대매매·큰 뉴스), 범 지갑 내역과 경제 리포트에 거래 기록.
- 운영 NPC는 아직 없음(창구만). 나중에 사장 NPC를 붙일 자리(`SHOP_INTERIORS.broker.owner`)를 비워 둠.

## 3. 시세 엔진

### 3.1 시간

- 게임 시간 = 실제 KST(기존 달력과 같음). 매일 열립니다(친구들은 주말에 더 놉니다).
- **틱**: 09:00, 10:00, …, 15:00 → 하루 7틱. 전역 틱 번호 `T = 일번호 × 7 + (시 − 9)`.
- **주문 가능**: 09:00 ≤ 시각 < 15:30. 15:00~15:30은 종가(15시 틱)로 체결되는 시간외 종가 구간. 그 밖은 **장외 — 주문 거부**(“장이 닫혀 있어요. 09:00~15:30에 주문할 수 있어요.”). 신용 상환은 돈만 갚는 일이라 장외에도 됩니다.
- 체결가: 지금 틱 가격에서 **매수는 매도1호가(+1호가 단위), 매도는 매수1호가(−1호가 단위)**. 호가 단위는 KRX식(2천 미만 1 · 5천 미만 5 · 2만 미만 10 · 5만 미만 50 · 20만 미만 100 · 그 위 500).

### 3.2 한 틱의 가격

```
r = σ·z                         z ~ N(0,1), 씨앗 해시로 만든 정규난수
  + κ·(목표 로그가 − 지금 로그가)   평균 회귀
  + 수급                           직전 틱 동안 친구들 순매수(3.4장)
  + 뉴스 충격                       그 틱에 잡힌 뉴스가 있으면
P(T) = 호가단위로 반올림(P(T−1)·e^r), [하한가, 상한가] 안으로 자름
```

- **09시 틱(시가)**은 밤사이 갭: σ가 더 크고(가게 1.0%, 테마 3.0%) 평균 회귀도 두 배.
- **목표가**(가게): `ln 시작가 + 0.12 × 거래액 신호 + 계절 + 날씨`. 거래액 신호 = `clamp(ln((최근 3일 평균 + K) / (최근 14일 평균 + K)), −1, 1)`, K = 3,000범. 그날 이전의 **이미 끝난 날**만 쓰므로 과거 시세가 나중에 바뀌지 않습니다. 장이 15:30에 닫히고 거래액은 자정까지 쌓이므로, 거래액 효과를 미리 완전히 알고 살 수는 없습니다.
- **목표가**(테마): `ln 시작가 + 0.25 × 주간 이야기(−1~1)`, κ는 작게(0.004) → 길게 출렁입니다.
- 가게: σ = 0.7%/틱, κ = 0.03. 테마: σ는 2.2장의 값.
- **상·하한가**: 전날 종가 ±15%(상한은 내림, 하한은 올림, 호가 단위). 가격이 닿으면 그날 한 번 “상한가/하한가” 사건으로 남깁니다.
- **뉴스 이벤트**: 날마다 종목마다 씨앗으로 굴립니다(가게 7%, 테마 20%). 걸리면 그날의 틱 하나(0~6)에 충격(가게 ±3~7%, 테마 ±6~13%)과 헤드라인(종목별 호재/악재 문구 표). 헤드라인은 **그 틱이 지난 뒤에만** 보여 줍니다.
- 최저가 50범.

### 3.3 결정성과 비밀 씨앗

- 난수는 `sha256(씨앗|종목|틱)`(동기 SHA-256 `lounge-sha256.ts`)에서 뽑습니다. 씨앗은 월드에 처음 증권 상태가 생길 때 서버가 `crypto.getRandomValues`로 만든 128비트 값이며 **응답에 절대 넣지 않습니다**(`stocksView`가 걸러 냄). 클라이언트 번들에 엔진 코드가 있어도 씨앗 없이는 미래 시세를 계산할 수 없습니다. FNV 같은 32비트 해시를 쓰면 상태가 32비트라 시세 몇 개로 씨앗을 역산할 수 있어서 SHA-256을 씁니다.
- 입력은 모두 고정된 값입니다: 씨앗, 틱 번호, 끝난 날의 거래액(원장 일별 집계), 그 틱 동안 기록된 순매수, 날씨·계절(달력 함수). 그래서 **언제 계산하든 같은 시세**가 나옵니다.
- **따라잡기(materialize)**: 상태에는 마지막으로 계산한 틱이 있고, 명령이 올 때마다 지금 틱까지 한 틱씩 계산합니다(배당·이자·마진콜·반대매매도 그 틱의 가격으로). 아무도 접속하지 않은 동안의 시세도 다음 접속 때 같은 결과로 채워집니다. 읽기 전용 요청은 메모리에서만 계산해 보여 주고 저장하지 않습니다(D-3 “읽기만으로 쓰지 않기” 유지). 테스트가 “한 번에 따라잡기 = 한 틱씩 따라잡기”를 확인합니다.
- 상장 때는 씨앗으로 상장 전 20일 시세를 미리 만들어 차트가 비어 있지 않게 합니다.

### 3.4 수급(친구 주문)과 시세 조종 방지

- 한 틱 동안의 순매수(매수 − 매도, 범)를 종목별로 모아, 다음 틱에 `0.6% × clamp(순매수 ÷ (시가총액 × 25%), −1, 1)`만큼 반영합니다.
- **조종이 손해가 되도록 숫자를 맞췄습니다**: 수급 효과의 최대치 **0.6%**는 왕복 비용(수수료 0.3% × 2 + 호가 차이 최소 0.1% = **0.7% 이상**)보다 작습니다. 혼자 산 뒤 다음 틱에 팔아도 기대값이 음수입니다. 친구 1명은 보유 한도(유통 주식 10%) 때문에 한 틱에 최대 0.24%밖에 못 움직이고, 여럿이 몰려도 0.6%에서 멈춥니다.
- 보유 한도: 종목당 **유통 주식의 10%**(롱·숏 각각). 시장 전체 공매도 잔고는 유통 주식의 30%까지.
- 체결은 언제나 서버의 지금 틱 가격으로 하고, 주문에는 가격 칸이 없습니다(가격을 보내면 거부). 같은 틱 안에서 사고팔아도 수수료와 호가 차이만 잃습니다.

## 4. 위험 장치 (신용 · 공매도)

### 4.1 숫자

| 항목 | 값 | 이유 |
|---|---|---|
| 거래 수수료 | 체결 금액의 0.3%(올림), 매수·매도 모두 | 왕복 0.6%가 수급 효과 최대치(0.6%)와 더해 조종을 막고, 잦은 단타를 줄이는 지출처 |
| 신용 매수 증거금 | 50% → **최대 2배** | 내 돈 1에 빚 1 |
| 신용 한도 | 친구당 **300,000범**(신용 매수 빚 + 공매도 진입 금액 합계) | 하루 판매 상한(10만)의 3배. 한 번의 폭락으로 잃을 수 있는 돈을 내가 넣은 증거금으로 묶음 |
| 신용 이자 | 빚의 **0.1%/일**, 매일 15:00 종가에 빚에 붙음 | 오래 끌수록 비용 |
| 공매도 증거금 | 진입 금액의 50% | 신용 매수와 대칭 |
| 대차 수수료 | 공매도 평가액의 **0.1%/일**, 15:00에 증거금에서 뗌 | |
| 공매도 배당 | 배당일에 공매도 수량만큼 배당금을 증거금에서 냄 | 실제 시장과 같음 |
| 마진콜 | 담보 비율 **40% 미만** | 경고(내 장부·알림). 다음 날 15:00 종가까지 40%를 회복하지 못하면 반대매매 |
| 반대매매(강제 청산) | 담보 비율 **30% 미만**이면 그 틱 가격에 즉시 | 마을 소식 한 줄 |
| 최대 손실 | **내가 낸 증거금 + 수수료** | 청산 대금이 빚보다 적으면(갭) 모자란 돈은 증권사가 떠안고 친구 지갑·은행 예금에서는 절대 가져가지 않음 |
| 종목당 보유 한도 | 유통 주식의 10% | 시세 조종 방지 |

담보 비율: 신용 롱 = (평가액 − 빚) ÷ 평가액, 공매도 = (증거금 + (진입가 − 현재가) × 수량) ÷ 평가액.

**갭 위험 점검**: 틱 사이 최대 변동은 같은 날 하한가 → 상한가(약 +35%)입니다. 반대매매 기준(30%)에서 롱은 가격이 다시 약 29% 더 떨어져야, 숏은 약 +54%가 더 올라야 증거금이 바닥나므로 대부분 증거금 안에서 끝나고, 그 너머는 위 “최대 손실” 규칙으로 막습니다.

### 4.2 신용은 카지노 대부업자(로제)와 별도 계좌

**결정: 별도 신용계좌.** 근거:

1. **담보가 다릅니다.** 로제의 대출은 담보 없는 현금 대출(단리 30%, 3일, 기한이 지나면 소지금·은행 예금에서 자동 회수)입니다. 신용 매수 빚은 산 주식이 담보이고 반대매매로 정리됩니다. 둘을 묶으면 주가 폭락이 로제의 자동 회수로 번져 **은행 예금까지 비는 연쇄**가 생깁니다. 별도 계좌는 손실을 “그 포지션에 넣은 증거금”으로 가둡니다.
2. **원장 불변식이 단순합니다.** 신용 빚은 실제 범이 오가지 않는 장부상의 숫자이고(증권사가 주식을 대신 들고 있음), 원장에는 친구 ↔ 하우스 사이의 실제 이동(증거금, 매도 대금, 배당)만 `marketNet`으로 남습니다. SQL 경제 리포트의 불변식(`잔액 + 예약 + 보관금 + 하우스 = 지갑 수 × 100,000 + 발행`)은 그대로 성립합니다.
3. **이자 체계가 다릅니다.** 로제는 한 번 붙는 30%, 신용은 하루 0.1%씩.

로제에게 빌린 범으로 주식을 사는 것까지 막지는 않습니다(범은 구분되지 않음). 대신 로제 빚은 로제 규칙대로, 신용 빚은 반대매매로 따로 정리됩니다.

### 4.3 경제 영향

- 시세 자체는 기대 수익 0(평균 회귀 + 대칭 노이즈)이고, 수수료(0.3% × 2)는 지출(`stock-fee`)로 빠집니다. 이자·대차 수수료도 증권사(하우스)에 남습니다.
- 들어오는 돈은 배당뿐: 가게 종목, 주마다 **종가의 0.4% × (지난주 거래액 ÷ 그 전 4주 평균, 0~2.5배)**. 7명이 100만 범씩 들어도 주 2만 8천 범 안팎으로, 오늘의 범(주 14만 7천 범)보다 훨씬 작습니다.
- 돈은 새로 찍히지 않습니다. 사고팔기·배당·청산은 모두 친구 ↔ 하우스 이동이고 원장 `marketNet`(“하우스 중 증권 순액”)으로 따로 집계합니다.

## 5. 주문과 서버 검증

액션 `{ kind: 'stock', op, sym, qty }`(가격 칸 없음):

| op | 이름 | 어디서 | 하는 일 |
|---|---|---|---|
| `buy` | 매수 | 증권사 안 | 매도1호가 × 수량 + 수수료를 지갑에서 냄 |
| `margin` | 신용 매수 | 증권사 안 | 절반은 내 돈(+수수료), 절반은 신용 빚 |
| `sell` | 매도 | 어디서나 | 매수1호가로 팔고, 신용분이면 빚(이자 포함)을 먼저 갚은 뒤 나머지를 지갑으로 |
| `short` | 공매도 | 증권사 안 | 매수1호가로 빌려 팖, 진입 금액의 50%를 증거금으로 냄 |
| `cover` | 환매수 | 어디서나 | 매도1호가로 되사서 갚고, 남은 증거금 + 차익을 지갑으로 |
| `repay` | 신용 상환 | 어디서나, 장외도 | `amount`만큼 그 종목의 신용 빚을 지갑에서 갚음 |

- 새로 위험을 지는 주문(매수·신용 매수·공매도)은 **증권사 안**(`player.area === 'broker'`)에서만. 위험을 줄이는 주문(매도·환매수·상환)은 마을 어디서든 메뉴의 “주식” 창에서 할 수 있게 해, 장 마감 직전에 마진콜을 받아도 손을 쓸 수 있습니다.
- 서버는 장 시간, 수량(정수, 보유 한도), 잔액, 신용 한도, 같은 종목 롱·숏 동시 보유 금지(먼저 정리), 마진콜 중 신용 추가 금지, 시장 공매도 한도를 확인합니다.
- 다른 친구가 볼 수 있는 것: 랭킹(수익률·손익)과 마을 소식뿐. 내 포지션·체결 기록은 나에게만 보냅니다.

## 6. 배당

- 주의 첫 장(월요일 09시 틱, `weekOf`가 바뀌는 날)에 지난주 기준으로 지급. 기준일은 직전 종가(일요일 15:00 이후 장외라 보유가 그대로).
- 주당 배당 = `내림(직전 종가 × 0.4% × clamp((지난주 거래액 + 7K) ÷ (그 전 4주 주평균 + 7K), 0, 2.5))`, 가게 종목만.
- 롱 보유자는 지갑으로(하우스 → 친구), 공매도는 증거금에서 냄. 내 장부와 범 내역에 “배당” 줄.

## 7. 화면

### 7.1 범마을 증권 건물

- **시장 거리 동쪽**(신문사와 우체국 사이 빈터, 문은 남쪽). kArchive 건물 모델 `realtyOffice`(신문사와 같은 사무실 건물, CC0·출처 표기 기존 그대로)를 짙은 남색 간판 “범마을 증권 · 주식 · 신용 · 공매도”로 구분합니다. 새 모델을 들이지 않아 에셋 예산과 출처 기록이 늘지 않습니다.
- **실내**는 가게 실내 공통 규격(`lounge-shop-interiors.ts`)의 다섯 번째 방 `broker`: 뒤쪽 시세 전광판(벽 간판 두 장 + 상단 띠), 객장 의자 줄, 상담 창구(계산대), 화분. 모델은 이미 출처가 기록된 kArchive/카페 가구(`cafeTable`, `register`, `storageShelf`, `teaSideboard`, `plantStand`, `banquetChair`)만 다시 씁니다.
- **사장 NPC 자리**: `SHOP_INTERIORS.broker.owner`를 비워 두고(`ownerAt`·창구 뒤 직원 통로는 이미 있음), 창구의 E는 바로 주식 창을 엽니다. 나중에 주민을 붙일 때는 `owner`에 NPC id, `npc-schedule`에 `broker.owner` 일과만 넣으면 됩니다.
- **미니맵**: 시장 거리 미니맵에 “범마을 증권” 문 표시(가게와 같은 방식, 자동), 실내에 있는 친구는 증권사 문 앞에 “실내” 점으로.

### 7.2 주식 창 (HTS 느낌)

- 왼쪽 **종목 리스트**: 종목명·현재가·등락률(오름 빨강, 내림 파랑 — 한국 관례), 상·하한가 배지, 가게/테마 구분.
- 가운데 **차트**: 오늘(1시간 7틱) 라인 / 최근 20일 일봉(캔들: 시가·고가·저가·종가) 전환, SVG로 직접 그림(외부 라이브러리 없음). 상·하한가 선 표시.
- **호가**: 매도1호가·현재가·매수1호가 세 줄만(단순화).
- **주문**: 수량 입력, 예상 금액·수수료·필요 증거금 표시, 버튼 매수 / 신용 매수 / 공매도 / 매도 / 환매수 / 신용 상환. 장외·위치·한도에 걸리면 버튼이 꺼지고 이유를 한 줄로 보여 줌(서버가 최종 판정).
- 오른쪽 **내 잔고**: 지갑, 평가 손익·수익률, 신용 사용/한도, 포지션(현금·신용·공매도, 담보 비율, 마진콜 경고).
- 탭: 시세 · 내 잔고 · 랭킹 · 소식(헤드라인·상하한가·배당·반대매매).
- 디자인 토큰만 사용(`app/ui/tokens.css`에 `[data-venue='broker']` 남색 계열과 `--stock-up`/`--stock-down` 추가), `npm run lint:css` 통과.

### 7.3 소식

- **마을 소식**(어제 마을 소식 다이제스트): 상한가·하한가(하루 종목별 한 번), 반대매매(친구 이름), 그날 가장 큰 주식 뉴스 한 줄. 주식 줄은 하루 최대 4줄로 다른 소식을 밀어내지 않게 함.
- **신문사**(잔나): 창구에 “주식 소식” 한 줄(가장 최근 헤드라인).
- **범 지갑**: “주식 거래” 최근 내역(매수·매도·배당·청산).

## 8. 저장 구조

`world.stocks`(월드 행 JSON, `CloudWorld`):

```ts
{
  v: 1,
  seed: string,            // 서버 전용, 응답에 넣지 않음
  listed: number,          // 상장 틱
  tick: number,            // 마지막으로 계산한 틱
  px: Record<sym, number>, // 지금 틱 가격
  days: Record<sym, [o,h,l,c][]>, // 최근 30일 일봉(오늘 포함)
  today: Record<sym, number[]>,   // 오늘 틱 가격
  flow: Record<sym, number>,      // 이번 틱 순매수(범)
  div: Record<sym, number>,       // 최근 주당 배당
  acct: Record<uid, { long, short, paidIn, paidOut, peak, call..., log }>,
  events: { at, sym, kind, text, actor? }[] // 최근 40개(헤드라인·상하한가·배당·청산)
  stats: { days: { d, fee, interest, borrow, dividend, absorbed, volume, liquidations }[] } // 30일
}
```

원장에는 `ledger.marketNet`(친구 → 하우스 순이동, 증권)만 늘어납니다. `validateLedger`의 하우스 식에 더하므로 불변식은 그대로이고, 수수료는 기존 `spendBeom('stock-fee')`(경제 리포트의 소비처 “주식 수수료”).

## 9. 테스트 (`tests/lounge-stocks.test.mjs`)

- 가격 결정성: 같은 씨앗·입력이면 같은 시세, 한 번에 따라잡기 = 한 틱씩 따라잡기, 씨앗이 다르면 다른 시세, 응답에 씨앗 없음.
- 상·하한가: 모든 틱 가격이 전날 종가 ±15% 안, 큰 뉴스는 한도에서 멈춤.
- 수수료: 0.3% 올림, 원장 `spent`와 `stock-fee` 집계.
- 신용: 2배 한도, 신용 한도 300,000범, 이자 누적, 마진콜(40%) → 다음 날 종가 반대매매, 30% 미만 즉시 반대매매.
- 공매도: 손실이 증거금 + 수수료를 넘지 않음(갭 상승 시 증권사가 떠안음), 대차 수수료.
- 배당: 주 첫 장에 지급, 롱은 지갑으로, 숏은 증거금에서.
- 장외 시간 주문 거부, 증권사 밖 신규 주문 거부(매도는 허용), 가격 칸을 보내면 거부(서버 권위).
- 원장 불변식이 모든 단계 뒤에 성립.

## 10. 나중에 정하면 좋을 것

1. **사장 NPC**: 누가 증권사를 맡을지(이름·성격·대사). 자리(`owner`)만 비워 둠.
2. **주말 휴장**: 지금은 매일 열림. 현실처럼 토·일 휴장으로 바꿀지.
3. **숫자 조정**: 신용 한도 30만, 이자 0.1%/일, 배당 0.4%/주, 테마주 변동성. 2주 정도 운영해 경제 리포트(“주식” 표)를 보고 맞추기.
4. **실제 사진·로고 없는 테마주 아이콘**: 지금은 글자 배지. 손그림 아이콘을 넣을지.
5. **가게 상장 확대**: 목장·과수원·산기슭 가게(3단계)가 생기면 종목 추가(`STOCKS` 표에 한 줄 + 거래액 버킷).
6. **랭킹 보상**: 주간 수익률 1등에게 칭호/트로피를 줄지(지금은 표시만).
