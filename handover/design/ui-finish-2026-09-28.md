# UI 마무리 점검 · 2026-09-28

`HANDOVER.md` 5장 첫 항목에 남아 있던 성장 수첩 대비와 지도 조작 가림을 재현해 수정했다. `handover/STYLE-AND-SOURCES.md`의 수첩·종이·갈색 잉크 방향을 유지했다.

## 원인과 수정

- **성장 수첩의 ‘고르기’**: 12px 글자 대비가 4.48:1이었다. 바탕과 모양은 유지하고 `--text-on-highlight` / `--highlight-soft` 의미 토큰으로 갈색 잉크를 적용했다. 장소별 토큰 검사에도 이 색 조합의 4.5:1 기준을 추가했다.
- **레벨 숫자의 잘못된 대비 경고**: Chromium이 혼합 배경을 `color(srgb …)`로 반환하면 검사기가 그 색을 읽지 못했다. 흰 숫자를 실제 초록 배지 대신 부모의 크림색 바탕과 비교하던 문제다. sRGB·선형 sRGB·알파 색을 해석하도록 보완했다.
- **지도 목록의 잘못된 가림 경고**: 목록 아래로 스크롤된 ‘다리 위 낚시’의 보이지 않는 사각형을 하단 채팅 버튼과 비교했다. 뷰포트와 스크롤 영역에 실제로 그려지는 부분에서만 가림을 검사한다. 일부만 보이는 버튼과 실제 겹침은 계속 검사한다.

수정 전 1920·1280 화면의 경고 10건 중 ‘고르기’ 2건은 실제 대비 부족이고, 레벨 배지 8건은 측정 오류였다. 지도 가림 1건도 측정 오류였다. UI의 배치나 겹침 순서를 바꾸어 수치를 숨기지 않았다.

## 검사기 보호 장치

- `scripts/ui-measure.mjs`로 측정 함수를 분리했다. 캡처 전에 작은 Chromium 화면 10개로 읽기 쉬운/어려운 혼합 색상과 실제/잘못된 가림 사례를 확인한다.
- `scripts/ui-report.mjs`가 예상 화면, 연관된 탭·게임 참가 화면, 지표, 캡처 실패, 브라우저 오류, 닫기 크기, 편집 Esc 결과를 검사한다.
- 화면이 빠지거나 측정이 실패하면 엄격 검사가 실패하고 기준 파일도 쓰지 않는다. 엄격 비교에 실패한 결과 역시 새 기준으로 저장하지 않는다.
- 기존 lucide 사용은 남아 있지 않았다. `app/ui/icons.tsx`는 자체 Glyph를 기존 이름에 연결하는 파일이므로 미감 가이드의 낡은 설명을 바로잡았다.

## 검증 범위

브라우저 검사는 외부 요청을 막은 로컬 모의 서버와 합성 계정으로 수행한다. UI 회귀 캡처는 1920×1080, 1440×900, 1280×720의 기본 화면 23개씩을 대상으로 하며, 별도의 `--games` 테이블 캡처는 이번 변경 범위에 포함하지 않는다. 서버 엔진·계정·원장은 수정하지 않는다.

로컬 검증 결과:

- `npm run check`: 타입 검사·테스트 636개·린터 통과. 이후 추가한 게임 참가 화면 누락 사례를 포함한 `node --test tests/ui-report.test.mjs`도 5개 모두 통과했다.
- `npm run lint:css`: 색·글자 크기·모서리·그림자·겹침 순서 위반 0건.
- `UI_KIT=1 npm run build:pages -- --out .ui-shots/pages --site-url /`: 성공. 기존 에셋 용량 경고 3건과 빌더의 `advancedChunks` 폐기 예정 경고는 남아 있다.
- `npm run ui:shots -- --pages .ui-shots/pages --views fhd,d,s --out .ui-shots/after --baseline scripts/ui-baseline.json --strict --write-baseline .ui-shots/after-baseline.json`: 69개 화면, 대비·작은 글자·좁은 줄바꿈·잘림·겹침·가려진 조작 모두 0건. 캡처/측정/브라우저 오류 0건, 닫기 크기·편집 Esc 실패 0건. 캡처 전 측정기 사례 10개 통과.
- 1920·1280의 성장 수첩과 지도를 눈으로 비교했다. 모양과 배치를 유지하면서 ‘고르기’ 글자가 또렷해졌고, 지도 목록은 스크롤 영역 안에 배치된다. 3D 소프트웨어 렌더링 부하로 일부 큰 화면에 보이는 연결 재시도 표시는 기존 로컬 하니스 제약이며, 이번 작업에서 서버 연결을 변경하지 않았다.

검증을 통과한 파일을 `scripts/ui-baseline.json`에 반영했다. CI는 기존처럼 1920·1280의 46개 화면을 검사하고, 1440의 23개 화면은 이번 로컬 검증에 추가했다. 결과 파일과 캡처는 로컬 `.ui-shots/after/`에 있으며 빌드 결과·캡처는 커밋하지 않는다. 배포 결과는 PR과 GitHub Actions 실행 기록에서 확인한다.

## 배포 중 발견한 기존 테스트 문제

UI PR #1의 CI(테스트 637개·UI 46개 화면)는 통과했지만 Pages가 테스트를 다시 실행할 때 기존 광산 소식 테스트가 무작위로 실패했다. 같은 커밋의 main CI 기본 검사도 통과해 재현 조건을 따로 확인했다.

`tests/lounge-regions.test.mjs`는 임의 UUID로 30일 동안 채굴한 뒤 마지막 상태에서 화석 소식을 찾았다. 광물·화석은 UUID에 따라 결정되며 소식은 최근 이틀만 보관하므로, 이전에 정상 지급된 화석의 소식이 마지막 검사 전에 사라질 수 있다. 고정 합성 계정으로 화석 14개가 정상 지급되고 당일 소식도 모두 생성됐지만 마지막 상태에는 소식이 없는 경우를 재현했다.

해당 테스트만 고정 계정으로 실행하고 화석이 지급될 때마다 같은 날의 소식을 확인하도록 바꿨다. 광물 분포·화석 지급량 검증은 유지했다. 기존 검증 실패 → 수정 후 지역 테스트 7개 통과를 확인했으며, 테스트 린트도 오류 없이 통과했다(기존 spread 경고 1건). 게임 엔진·소식 보관 기간·지급 규칙은 수정하지 않았다.
