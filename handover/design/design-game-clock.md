# 게임 시계: 게임 하루 = 실제 1시간 (2026-10-02)

## 1. 왜 바꾸나

지금까지 범타듀 밸리는 게임 시각 = 실제 KST 시각(1:1)이었다. 그래서 하루 중
일부 시간에만 있는 것이 친구들이 못 들어오는 시간에 몰렸다.

- 새벽 경매(06~07시), 새벽 물고기(빙어·꽃송어 05~10시), 새벽 선장 초대(05~07시, sea-fishing)
- 주식 장(09:00~15:30, stock-exchange): 다들 학교·회사에 있는 시간
- 주민의 낮 일과(가게 앞 좌판, 배달, 순찰): 저녁에 들어오면 늘 밤 장면만 본다

친구들은 대부분 20:00~01:00에 들어온다. 그 다섯 시간 동안 하루의 모든 시간대를 볼 수 있어야 한다.

정리: 실시간(1:1)인 게임은 늘 "그 시간에 못 들어간다"는 문제가 생기고, 스타듀형(세션 동안만 흐름)은 서로 다른 시간에 들어오는 친구들이 같은 하루를 공유할 수 없다. 범타듀는 **같은 마을에 친구 7명이 각자 시간에 들어오는** 구조라 팔리아 방식(공용 시계, 하루 1시간)이 가장 맞다.

## 3. 결정 (사용자 결정, 2026-10-02)

- **게임 하루 = 실제 1시간.** 게임 1시간 = 실제 2분 30초, 게임 1분 = 실제 2.5초.
- 게임 자정은 실제 매시 정각(:00)이다. KST는 UTC+9로 정시 단위라 **게임 하루는 실제 KST 하루를 절대 걸치지 않는다.** (실제 23:00~24:00 시간이 그 실제 날의 마지막 게임 하루.)
- 시계는 `now`(서버 시각)만으로 결정된다: 서버·모든 클라이언트가 같은 값을 계산하고, 아무도 없어도 흐른다. 저장할 상태가 없다.
- 게임 하루 번호 `gameDay(now) = floor(now / 1시간)` (에포크부터의 실제 시간 번호). 실제 KST 날짜 `realDayOfGameDay(g) = kstDay(g × 1시간)`.
- **'분위기·일과(시간대)'만 게임 시계, '경제 횟수·성장·달력'은 실제 날짜.**

시간대 경계는 그대로: 새벽 05~08, 낮 08~17, 저녁 17~20, 밤 20~05 (게임 시각). 실제 시간으로는 한 시간마다 새벽 7분 30초, 낮 22분 30초, 저녁 7분 30초, 밤 22분 30초.

### 3.1 API (`app/lounge-calendar.ts`)

| 이름 | 뜻 |
| --- | --- |
| `GAME_DAY_MS` / `GAME_HOUR_MS` / `GAME_MINUTE_MS` | 3,600,000 / 150,000 / 2,500 |
| `gameDay(now)`, `gameDayStart(g)` | 게임 하루 번호와 그 시작 시각 |
| `gameHour(now)`, `gameMinute(now)`, `gameMinuteOfDay(now)`, `gameHourFrac(now)` | 게임 시각 |
| `gameTimeAt(g, h, m)` | 게임 하루 g의 h:m 이 실제로 언제인지 |
| `nextGameTime(now, h, m, ok?)` | now 이후 처음 오는 게임 h:m (ok(실제 KST 날)로 요일 거르기) |
| `realDayOfGameDay(g)` | 게임 하루가 속한 실제 KST 날 |
| `timeOfDay(now)`, `isDaytime`, `isNighttime` | **게임 시계** 기준 |
| `gameClockText(now)` | HUD 시계 "오후 3:20" (게임 10분 단위) |
| `realKstHour(now)` | 실제 KST 시(0~23). 옛 `kstHour`. 실제 시간이 꼭 필요한 곳만 |

옛 `kstHour`(lounge-calendar, lounge-village-life 두 곳)는 없앴다. 이름만 보고 실제/게임을 헷갈리지 않게, 쓰는 쪽이 둘 중 하나를 고르게 했다.

## 5. 바뀐 영업·행사 시간과 근거

게임 하루가 실제 1시간이라 게임 시각 창의 실제 길이는 (게임 시간 × 2.5분)이다. 원래 창을 그대로 두면 너무 짧아지는 것만 넓혔다. 기준: "들어와 있는데 실제 20분 넘게 계속 닫혀 있어 불편하지 않게", 그리고 행사 창이 실제 5분보다 짧지 않게.

| 행사 | 전 (KST) | 후 (게임 시각) | 실제로는 매시간 |
| --- | --- | --- | --- |
| 새벽 경매 | 06~07 | **05~08** (새벽 전체) | 7분 30초 열림 |
| 독서 모임 (실제 수요일) | 19~21 | **18~22** | 10분 |
| 공연 밤 (실제 화·금) | 20~22 | **19~23** | 10분 (보치 무대 19:30~22:30과 맞춤) |
| 금요 카지노의 밤 (실제 금요일) | 18~24 | **18~06** | 30분 (테이블 한 판이 창 끝에 걸려 놓치지 않게) |
| 토요일 밤 등불 상점 (실제 토요일) | 19~24 | **18~06** | 30분 열림 · 30분 닫힘 (닫힌 쪽은 낮이라 "밤에만 여는 가게" 성격 유지) |

일반 가게(농협·잡화점·빵집·어시장·주점·가구점·부동산·은행·미용실·카지노·회관)는 원래 영업시간 제한이 없다(주인이 자리를 비워도 카운터는 열린다). 그대로 둔다. 주민이 가게에 없는 게임 밤은 실제 최대 약 20분이다.

주민 일정은 시각을 그대로 두고 게임 시계로만 옮겼다. 다만 럭스는 새벽 경매가 05~08로 늘어 `hb.auction` 05:00 → 어시장 08:00으로 맞췄다.

## 6. 주민 일정 구현 메모

- `npcTimeline(id, g)`의 g는 이제 **게임 하루 번호**. 일정의 hh:mm은 게임 분(2.5초)으로 실제 시각이 된다: `gameDayStart(g) + hhmm × GAME_MINUTE_MS`.
- 걷기·문/구역 통과 시간은 실제 초 그대로(걸음 속도 2.1, 문 5초, 구역 문 20초). 게임 분으로는 길어 보이지만(구역 문 20초 = 게임 8분) 다음 일정이 밀리면 기존처럼 도착 뒤에 시작한다(`Math.max(t, …)`).
- 요일·날씨·장날·축제(`dayKind`)는 `realDayOfGameDay(g)`. 늦잠·배달 순서·취재 장소·저녁 자리 배정 같은 변화용 시드는 게임 하루 번호(g)로 바꿔 매 게임 하루 달라진다.
- 밤 자리(19:30 저녁, 22:30 늦은 자리, 01:00 취침)는 그대로 게임 시각. 어제 늦은 자리는 "이전 게임 하루"(g−1)의 것.
- `npcPlan(id, g)`, `gameDayStart`(옛 `kstDayStart`)도 게임 하루 기준.
- 마켓 점검 스크립트의 `bumtadew:npc-clock`은 그대로(시각 이동 ms).

## 8. 병합 후 맞춘 것 (claude/broker-muzan 병합, 2026-10-02)

처음에는 "병합할 때 이렇게 맞춘다"는 규칙이었다. `claude/broker-muzan`(main + 먼바다 낚시 + 3단계 주민 + 지점장 무잔 + 범마을 증권 + 가구 + 물고기 가격·민물 어종)을 병합하면서 아래처럼 맞췄다. 원래 규칙과 다르게 한 곳은 이유를 적었다.

### 8.1 범마을 증권 (`app/lounge-stocks.ts`)

**시계와 틱 번호**

- 장은 **게임 하루마다** 열린다: 게임 09:00~15:30 주문(실제로는 매시 22분 30초~38분 45초, 16분 15초). 시세는 게임 09~15시 정각, 게임 하루 7틱, **실제 하루 168틱**(2분 30초마다).
- 틱 번호는 시각만의 순수 함수: `T = gameDay(now) × 7 + (게임 시 − 9)`, `tickAt(T) = gameTimeAt(⌊T/7⌋, 9 + T mod 7)`. 서버에 따로 저장하는 시계가 없고, 지난 틱의 입력이 고정이라 한 번에 따라잡든 조금씩 따라잡든 같은 시세다(테스트: "deterministic", "catching up after days offline").
- 상태 버전 `v: 2`. 이미 저장된 v1 장부(실제 하루 7틱, `T = 날 × 7 + 시 − 9`)는 `readStocks`가 읽을 때 옮긴다: 저장된 틱(현재·상장·뉴스·마진콜 시각)을 같은 실제 순간의 게임 틱으로 바꾸고, 가격·기준가(전날 종가)·일봉·통계는 원래 실제 날 기준이라 그대로 쓴다.

**"하루"는 실제 KST 하루로 통일**

±15% 가격제한폭을 게임 하루에 걸면 실제 하루에 24번 걸려 하루 최대 ±(1.15²⁴) 같은 폭주가 가능하고, 규칙 초안의 "게임 ±3% + 실제 ±15% 이중 밴드"는 뉴스 충격(3~7%)이 게임 밴드에 잘려 상한가가 너무 자주 찍힌다. 그래서 **돈과 기록의 하루는 전부 실제 KST 하루**로 맞췄다(일일 횟수·초기화가 실제 날이라는 이 문서의 원칙과 같다).

| 항목 | 기준 |
| --- | --- |
| 상·하한가 ±15% | **직전 실제 날의 마지막 종가** 기준 하나만. 상한가·하한가 소식도 실제 날마다 종목당 한 번 |
| 일봉(20일 차트), `prev`(전일 대비) | 실제 날 (게임 하루 24개를 한 봉으로) |
| 신용 이자·공매도 수수료 0.1% | 실제 날 1번, **그 실제 날의 마지막 종가**(실제 23시대 게임 하루의 15:00 틱)에. 초안의 "첫 종가" 대신 원래 규칙("장 마감에 하루치")과 같은 자리에 두었다 |
| 마진콜 → 반대매매 | 콜이 실제 하루(168틱) 넘게 풀리지 않으면 실제 날 마감에 정리(원래 "다음 날 종가"와 같음). 30% 아래는 바로 다음 틱 |
| 배당 | 실제 월요일의 첫 틱(실제 주) |
| 뉴스 충격 | 실제 날마다 종목당 최대 1번(확률은 그대로), 168틱 중 하나에 |
| 통계(`stats`) | 실제 날 |
| 오늘 시세 차트(`today`) | **지금 게임 하루**의 7틱 (2분 30초마다 점 하나 — 들어와 있는 동안 장 하나가 다 보인다) |

**변동성 재조정** (`perTick`)

종목 정의의 σ·밤사이 σ(gap)·κ는 "실제 하루 7틱" 값 그대로 두고, 가격을 만들 때 틱당 값으로 바꾼다.

- σ' = σ / √24, 밤사이 σ' = gap / √24 (게임 하루 시작 틱에) → 실제 하루 분산 24 × (7σ'² + gap'²) = 7σ² + gap²
- κ' = 1 − (1 − κ)^(1/24) (24틱 당김 = 원래 1틱)
- 친구 순매수 효과 상한 `STOCK_MAX_IMPACT` 0.006 → **0.0012** (0.6% / √24 ≈ 0.12%, 같은 순매수가 하루 24번 반영되지 않게; 왕복 비용 0.6%+보다 여전히 작다)

| 종목 | σ 틱당 | gap 틱당 | κ 틱당 | 실제 하루 σ 목표 | 실측(90일, 뉴스 포함) |
| --- | --- | --- | --- | --- | --- |
| 가게 9종 | 0.00143 | 0.00204 | 0.00127 | 2.10% | 1.5~2.8% |
| 범성전자 | 0.00367 | 0.00612 | 0.00042 | 5.63% | 6.1% |
| 범이닉스 | 0.00449 | 0.00612 | 0.00042 | 6.55% | 5.6% |
| 범비디아 | 0.00531 | 0.00714 | 0.00042 | 7.72% | 6.0% |

90일 동안 ±15%에 닿은 날은 테마주만 0~3일(가게주 0). 테스트 "a real day of 168 game ticks moves about as much as the old seven-tick day"가 종목마다 실제 하루 σ가 목표의 0.5~1.8배 안인지 본다.

**따라잡기 비용**: 실제 하루가 168틱이라 상장 때 미리 만드는 20일 이력이 3,360틱(약 0.5초, 한 번)이다. 오래 비운 장은 최근 7일만 전부(이자·배당·마진콜 포함), 그 앞 21일은 조용히(가격만), 더 앞은 가격을 그대로 두고 건너뛴다(요청 하나의 일을 묶어 둔다).

**화면**: 장 상태 "장중 · 다음 시세 게임 오전 10:00 (실제 20:25)", "장 마감 · 다음 개장 게임 오전 9:00 (실제 …)", 차트 "오늘 장(게임 1시간)" / "일봉(실제 20일)", 닫힘 안내 "게임 시각 09:00~15:30(실제로는 매시 22분~38분)". 무잔의 창구 한마디도 장 시작·마감·배당 아침을 게임 시각으로 판단하고(반대매매·뉴스는 실제 날), 대사 회전은 게임 1시간마다.

### 8.2 먼바다 출항 (`app/lounge-voyage-data.ts`, `lounge-voyage.ts`)

- 출항: **게임 05:00~19:00 매 게임 정시**, 게임 하루마다 15척(실제 1시간에 15척, 2분 30초 간격, 실제 하루 360척). `sailingsOf(게임 하루)`, `boardingSailing`, `nextSailing`이 게임 시계. 승선은 출항 2분(실제) 전부터.
- 항해는 **실제 20분 그대로**(게임 8시간). 하루 1회 승선(`days`), 승선료, 멀미약(실제 자정까지)은 실제 날.
- 새벽 선장 초대: **게임 새벽 05~07시**(`inDawnHours` → `gameHourOf`). 실제 날마다 한 번만 답할 수 있고(`knock.day` = kstDay), 답하지 않은 채 새벽이 지나가면 **다음 게임 새벽(실제 최대 1시간 뒤)에 다시 온다** — 접속하지 않은 사이 지나간 새벽은 놓친 것으로 치지 않는다. 초대 배는 수락 3분(실제) 뒤 출발.
- 항구의 허 선장(배 옆에 서 있는 시간)도 게임 05~19시.
- 안내판: "게임 오전 10:00(실제 20:25) 출항", "게임 시각 05~19시 매 정시(실제 2분 30초마다)".

### 8.3 주민 일정 (3단계 주민, 무잔, 로제·루미·매화)

- 새 주민의 `planOf` 시각은 게임 시각으로 읽힌다. 3단계 구역이 닫혀 있을 때의 자리(`dayPlan`, `STAGE3_HOME`)도 게임 하루마다 같은 판정.
- **신이치의 천막 날**(주말·축제)은 실제 날: `fortuneOpenOn(realDayOfGameDay(g))`. 천막 날 다음 첫 게임 하루 새벽 1시까지 늦은 자리에 있다가 마을을 떠난다.
- 걷기는 실제 초라 먼 곳으로 가는 짧은 일정이 거의 보이지 않던 것을 늘렸다:
  - 무잔 일요일: 빵집 점심 12:00 → 항구 산책 **12:50 → 14:00** (항구는 구역 문 둘 너머)
  - 로제 쉬는 시간: 방파제 노을 **17:30~18:30 → 17:00~19:00**
  - 메르시: 왕진 **17:00 → 16:30**, 저녁 진료 **18:30 → 18:00**
- **한 자리에 두 주민이 서지 않게**: 게임 하루 단위로 시드가 바뀌면서 비 오는 날 봇치(항구 창고 연습)와 야니네코(창고 처마)가 겹치는 경우가 나왔다. 야니네코의 비 오는 오후를 어시장 처마(`fishmarket.browse`)로 옮겼다. 테스트 "no two residents share a spot at once"가 실제 7일 × 게임 하루 2개 × 게임 5분마다, 구역이 닫힌/열린 마을 둘 다에서 보이는 자리의 겹침을 막는다(집·마을 밖 같은 숨은 자리는 제외).
- 신이치 운세의 작은 행운(3시간)은 요리 버프처럼 **실제 시간** 타이머로 두었다.

### 8.4 물고기 (신선·바다 어종)

- 새 어종의 `hours`·낮/밤·새벽은 모두 게임 시각(`fishAvailable`의 `gameHour`). 병합 뒤 시각 창은 전설 빼고 모두 게임 3시간 이상이라(가장 짧은 일반 어종: 꾸구리 05~09) 넓힐 것이 없었다. 바다 위 물고기도 같다(배 위에서 게임 8시간이 흐른다).
- 판매 수요(같은 어종 4마리 정가)와 가격은 실제 날 그대로.
- 테스트(fresh-fish, voyage)의 시각 표본은 "실제 날 × 게임 시"로 바꿨다. `scripts/sea-fishing-economy.mjs`도 게임 시각으로 시작 시각을 찾는다.

### 8.5 로제·루미·매화

근무·산책 시각은 게임 시각, 쉬는 날은 실제 요일(`HOST_DAY_OFF`, `k.weekday`) 그대로. 위 8.3의 로제 쉬는 시간만 늘렸다.
