# 시간 체계 개편 + 엔드게임 (2026-10-03)

스팀 유저 시점 리뷰에서 가장 크게 깎인 두 가지를 고친다.

1. **시간 체계**: 작물·일일 제한·계절이 실제 날짜에 묶여 있어서 몰아서 할 수 없다. 매일 접속을 강요하는 모바일 게임 리듬이 된다.
2. **엔드게임**: 메인 목표·이야기가 없고, 연구 V5–V9가 준비 중이고, 광산이 20층에서 끝난다. 30일쯤 지나면 할 게 주식과 도박뿐이다.

공통 원칙
- **공용 마을은 그대로 둔다.** 친구 7명이 같은 하늘·날씨·계절·축제를 본다. 이게 이 게임의 가장 큰 장점이다.
- **개인 진도만 풀어 준다.** 내 밭, 내 일일 활동, 내 관계는 내가 몰아서 할 수 있게 한다.
- **돈이 갑자기 늘어나지 않게 막는다.** 통화량이 120일 동안 1.07배로 잡혀 있는 지금의 균형(재점검 종합 문서)을 깨지 않는다.

## 1부. 시간 체계: "마을의 날"과 "나의 하루"

### 1-1. 지금 어떻게 되어 있나

| 시계 | 쓰는 곳 | 코드 |
| --- | --- | --- |
| 게임 시계 (게임 하루 = 실제 1시간) | 시각대, 조명, 주민 일과, 물고기 시간대, 주식 장, 배 출항 | `app/lounge-calendar.ts` `gameDay` 등 |
| 실제 KST 날짜 | 일일 제한 거의 전부, 출하함 정산, 까마귀, 숲 채집, 광산 배치, 대화·선물, 성장 XP 상한, 동물 돌봄 | `app/lounge-economy.ts:590` `kstDay` |
| 실제 밀리초 | 작물 성장(`growMs`), 과일 재수확 6시간, 대출 만기 | `app/lounge-life.ts:191-237` |
| 실제 7일 | 계절, 1년 = 28일 | `lounge-calendar.ts:15-21` |

- 잠자기·체력은 없다. 침대는 기분(휴식) +50만 준다(`lounge-mood.ts:782`).
- 문제는 이것이다.
  - 주말에 3시간 하는 친구는 1시간 만에 오늘 할 일(채집, 광석, 대화, 선물, 의뢰)이 바닥난다.
  - 작물은 실제 시간이 지나야 자란다.
  - 며칠 빠지면 동물 애정과 친구 관계가 깎인다.

### 1-2. 결정안

**A. "하루 마감" (내 침대에서 잠자기)**
- **언제**: 내 방 침대에서, 게임 시각 20:00~05:59 사이에 할 수 있다. 밤은 실제 시간으로 매시간 약 25분씩 온다.
- **횟수**: 실제 하루에 최대 2번(`EXTRA_DAYS_PER_REAL_DAY = 2`).
  - 실제 자정에 저절로 넘어가는 하루까지 합쳐, 실제 하루에 최대 **3개의 '나의 하루'**를 쓸 수 있다.
  - 세 번째부터 침대는 지금처럼 기분 회복만 한다. 안내 문구: "오늘은 충분히 잤어요."
- **잠자면 일어나는 일 (나에게만)**
  1. **나의 하루 +1.** 개인 활동 제한이 초기화된다(1-3 표).
  2. **내 밭의 작물 시계 +12시간**(`SLEEP_GROW_MS`). 과일나무 재수확 대기도 같이 줄어든다.
  3. **출하함 즉시 정산.** 자정까지 기다리지 않는다.
  4. **하루 결산 카드**를 보여 준다(스타듀의 하루 끝 화면): 출하 수입, 자란 작물, 오른 기술, 오늘의 기분.
- **공용 시계는 그대로 흐른다.** 화면이 잠깐 어두워졌다가 결산 카드를 보여 주고, 같은 밤으로 돌아온다. 이름도 '잠자기'가 아니라 **'하루 마감'**으로 해서 어색함을 줄인다.
- **다른 사람에게는**: 내 아바타 위에 💤가 30초 동안 뜬다. 접속은 유지된다.

**B. 나의 하루 번호 (`pday`)**
- `pday = kstDay(now) + u.bonus`. 하루 마감을 하면 `bonus += 1`.
  - 실제 자정이 지나면 `kstDay`가 1 늘어서 `pday`도 저절로 1 늘어난다.
  - `pday`는 줄어들지 않고 항상 `kstDay` 이상이다. 그래서 지금 실제 날짜로 저장하던 값(`ext.day`, `u.day`, `talkedDay` 등)과 섞여도 `===`·`>=` 비교가 안전하다.
- 실제 하루당 하루 마감 횟수는 `u.slept = { d: kstDay, n }`로 센다.
- `bonus`는 저장 값으로 남는다. 마이그레이션이 필요 없다. 새 필드를 기본값 0으로 읽는다.

### 1-3. 무엇을 '나의 하루'로, 무엇을 '마을의 날'로 바꾸나

| 구분 | 항목 | 기준 | 이유 |
| --- | --- | --- | --- |
| 개인 활동 | 숲 채집 `taken`, 벌레, 광석 `mrock`·광맥, 광산 층 배치, 오늘의 기분 간식·음료 | **나의 하루** | 몰아서 할 수 있게 하는 것이 핵심 |
| 개인 활동 | 주민 대화·선물·데이트 (`talkedDay` 등) | **나의 하루** | 관계를 몰아서 쌓을 수 있게 함. 호감 상한과 하트 이벤트로 속도를 조절 |
| 개인 활동 | 친구 의뢰 `req`, 주민 의뢰판 | **나의 하루** | 단, 하루 보수 상한 3,000 범은 실제 날짜 기준으로 유지 |
| 개인 활동 | 기술 XP 일일 상한 `dxp` | **나의 하루** | 상한 자체를 유지하고 하루 수만 늘어남 |
| 개인 활동 | 동물 돌봄 `a.last` | **나의 하루** | 내 동물이니 내 하루 기준 |
| 돈 | 판매 상한 `SELL_CAP_PER_DAY`, 판매 수요 곡선 `dem`, 매일 받는 돈 `ledger.daily` | **마을의 날 (그대로)** | 돈이 갑자기 늘지 않게. 하루 마감으로 더 버는 건 작물·물고기 수확량뿐 |
| 공용 | 날씨, 계절, 축제, 요일 행사, 주민 일과, 가게 재고, 주식, 품평회, 낚시 대회, 부동산 | **마을의 날 (그대로)** | 친구들이 같은 마을을 봐야 함 |
| 공용 | 연구 완료(06:00), 대장간 수령 | **마을의 날 (그대로)** | 공동 목표 |

- 판단 기준: **돈 상한은 실제 날짜, 즐길 거리는 나의 하루.**
- 몰아서 하는 친구는 하루에 할 일이 최대 3배가 되지만, 버는 돈 상한은 같다. 그 시간에 관계, 기술, 수집(박물관, 도감, 꾸러미)에서 앞서 나간다.

### 1-4. 부재 보호 (빠진 날 벌 주지 않기)

| 지금 | 바꿀 것 |
| --- | --- |
| 실제 날짜 차이만큼 친구 관계 감소 (`decayedBond`) | 마지막 접속 뒤 **최대 3일만** 감소로 계산 |
| 동물 애정이 `day - a.last - 1`만큼 깎여 0까지 감 | **목장 도우미**: 이틀 넘게 비우면 동물 돌봄을 자동으로 처리(하루 200 범, 동물 한 마리당). 범이 모자라면 애정 감소를 최대 2까지로 제한 |
| 휴식 XP는 이미 있음 (`REST_MAX`) | 그대로. 결산 카드에 "푹 쉬고 왔어요: 다음 XP 2배" 표시 |
| 놓친 일일 활동은 사라짐 | **주간 묶음**: 이번 주에 못 쓴 채집·광석 기회를 최대 3일분까지 하루 마감 때 '밀린 기회'로 돌려줌. 판매 상한은 제외 |

### 1-5. 계절

- 계절 7일, 1년 28일은 **그대로 둔다.**
  - 친구들이 같은 계절을 보고, 설날·추석이 실제 날짜와 맞는 게 장점이다.
  - 하루 마감으로 한 계절에 최대 21개의 '나의 하루'가 생긴다. 이제 스타듀의 28일에 가깝다.
- 계절이 끝날 때 작물이 바로 시드는 문제는 **'막바지 수확 보장'**으로 푼다. 계절 마지막 날 전에 다 자란 작물은 다음 계절 첫날 06:00까지 시들지 않는다(`witherAt` +30시간).

### 1-6. 화면

- **HUD 시계**: `가을 3일 · 저녁 7:40` 옆에 `나의 하루 +1` 배지를 띄운다. 오늘 하루 마감을 몇 번 했는지 보여 준다.
- **침대 상호작용**
  - 게임 밤이면 `하루 마감하기 (오늘 2번 남음)`이 나온다.
  - 낮이면 회색으로 표시하고 "밤 8시부터 할 수 있어요"라고 안내한다.
- **결산 카드**: 1~2초 페이드 → 카드 → 아무 키나 누르면 닫힌다. 효과음은 짧은 오르골 징글(Suno 문서의 `day-end`).

### 1-7. 구현 메모

- **새 순수 함수**: `myDay(u, now)`, `canEndDay(u, now)`, `endDay(world, uid, now)`. 파일은 `app/lounge-myday.ts`이고 서버·클라이언트가 같이 쓴다.
  - `endDay`: 작물 시계 이동(`Plot.plantedAt -= SLEEP_GROW_MS`, `wateredAt`·과일 대기도 같이) → `settleBin` → `bonus++` → 결산 요약 반환.
- **교체**: 1-3에서 '나의 하루'로 정한 항목의 `kstDay(now)` 호출을 `myDay(u, now)`로 바꾼다.
  - 대상: `todayExt`, `userToday`, `lounge-stage3 stateOf`, `lounge-romance`의 일 단위 필드, `lounge-mood today()`.
  - 같은 계산을 여러 곳에 손으로 써 둔 실제 날짜 공식(`lounge-area-3d.tsx` 등 6곳)은 `kstDay`로 먼저 모은다.
- **Edge API**: `op: 'endDay'` 하나 추가. 서버에서 시각·횟수 제한을 다시 확인한다.
- **테스트**
  - 하루 3번 상한.
  - 판매 상한이 실제 날짜 기준으로 유지되는지.
  - `pday`가 줄어들지 않는지.
  - 자정을 걸친 하루 마감.
  - 출하함 즉시 정산.
  - 작물이 정확히 +12시간 자라는지.
  - 부재 보호(관계 최대 3일, 동물 도우미 과금).
  - 기존 `lounge-game-clock`의 '채집은 실제 하루에 한 번' 테스트는 '나의 하루에 한 번'으로 고친다.

### 2-2. 이야기 엔진: 촌장의 편지 (데이터 기반)

새 파일 `app/lounge-story-data.ts`와 `app/lounge-story.ts`.

```ts
type Chapter = {
  id: string;            // 'a2-ranch-1'
  act: 2 | 3 | 4;
  title: string;         // '울타리를 세우자'
  needs: Need[];         // 시작 조건: 연구 완료, 마을 플래그, 날짜, 이전 장
  steps: Step[];         // 마을 공동 진행 (기여한 친구 기록)
  letter: string;        // 촌장 편지 본문 (우편함으로 배달)
  scene?: SceneLine[];   // 완료 장면: 주민 대사 3~6줄, 일러스트 1장(선택)
  reward: Reward;        // 플래그, 가구, 레시피, 범(기여자 전원 같은 액수)
};
type Step =
  | { kind: 'deliver'; item: string; qty: number }               // 공동 납품 (꾸러미처럼)
  | { kind: 'reach'; what: 'mineFloor' | 'museum' | 'fishJournal'; n: number }
  | { kind: 'talk'; npc: string; window?: [number, number] }     // 게임 시각대
  | { kind: 'gather'; place: string; friends: number; window: [number, number] } // N명이 같은 장소에 동시에
  | { kind: 'research'; code: 'V5' | 'V6' | 'V7' | 'V8' | 'V9' };
```

- **공용 진행**: 한 장은 마을 전체가 함께 진행한다. 누가 무엇을 했는지 `by`에 기록하는 방식은 연구(`ResearchState.by`)와 같다.
- **`gather` 단계**: 친구 N명이 같은 게임 시각대에 같은 장소에 있어야 하는 단계다.
  - 이 게임만의 강점(같이 하는 시간)을 이야기 진행에 쓴다.
  - 막 하나에 1번만 두어 부담을 줄인다. 진행 표시: "부두에 친구 4명이 모이면 시작해요 (지금 2명)".
- **편지 배달**: 기존 친구 편지 우편함(`lounge-life.ts:638`)을 쓴다. 주 1회 정도 새 장이 열리게 조건을 단다.
- **주민 하트 이벤트**: 주민마다 하트 2·4·6·8에서 짧은 장면 하나씩. 기존 고백·연애(`lounge-romance.ts`)와 연결한다.
  - 처음에는 대사가 많은 주민 6명부터 시작한다.

### 2-6. 돈 흐름 점검

- **새로 빠져나가는 돈**

### 2-8. 사용자가 정할 것

1. 하루 마감 횟수: 실제 하루에 추가 2번(총 3일분)이 적당한지.
2. 등대 결말의 기여 인원: 5명(14일 뒤 3명)이 적당한지.
3. `gather` 단계(친구 N명이 동시에 모이기)를 이야기에 넣을지. 넣는다면 막마다 1번.
4. 친구 7명의 생일·선물 취향: 4막의 친구 하트 이벤트에 필요하다.
